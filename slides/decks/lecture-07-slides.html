Lecture 07 — Debugging as a Method

Learning objectives

  • Reproduce a defect with a minimal input
  • Form hypotheses and test them one at a time
  • Read error messages as evidence, not noise

Case-based lecture: you attempt, we discuss, then we reveal.

Key definitions

Key definitions

  • Defect (bug) — code that does not meet its specification - distinct from a mistake you have not yet observed.
  • Symptom — the observed wrong behaviour; often far from the defect's location.
  • Reproduction — a specific input and sequence that makes the symptom appear on demand.
  • Hypothesis — a testable claim about the cause; good hypotheses predict an experiment's result.
  • Isolation — cutting the search space in half (or deleting code) until the defect is cornered.
  • Regression test — a test that fails if a fixed defect ever returns.
Explain each in one breath; the cases will do the heavy lifting.
Worked example

The missing first item: reproduce, hypothesise, isolate

cs-025

Items [2.00, 3.50, 1.25] print a receipt of 4.75 instead of 6.75. Debug it by the method: reproduce, hypothesise, isolate, fix, verify.

Expected: 4.75 6.75

Cost: Debugging cost, not runtime: one repro, one minimal input, one rerun. The method's value is that it terminates.

Worked example

The ghost duplicate: aliasing proved by identity

cs-027

A task board shows one task list twice after a second edit. Prove the cause and fix it.

lines = ["a", "b"]
echoed = []
for i in range(len(lines)):
    echoed.append(lines[i])
print(len(echoed), echoed[0])

Expected: duplicated rows with identity True; after the fix the rows differ and the check is False

Cost: O(k) extra per call for the copy - correctness buys the copying cost.

Case cs-025 · Beginner

The Case of the Missing Sales

A receipt program prints a total that is too low by exactly one item's price. Form hypotheses, design the minimal reproducing input, and localise the fault.

  • **Input:** items [2.00, 3.50, 1.25]; receipt printed 5.50
  • **Output:** one item skipped (1.25 missing); repro input: 3 items, expected 6.75
  • Solve for the worked instance first. Then ask what would change if one
  • number, name, or condition were replaced by something stranger.

Case cs-026 · Foundational

The Off-by-One Invoice

An invoice tool includes one extra row under specific conditions. Use bisection over input shapes to find the boundary condition that triggers the defect.

  • **Input:** invoice rows; extra row appears only when qty is exactly 10
  • **Output:** boundary bug: condition qty >= 10 should be qty > 10; minimal repro: one row qty=10

The Ghost Duplicate

  • **Output:** aliasing: the same list object referenced twice; is-check (a is b) proves it

Case cs-028 · Advanced

The Heisenbug

A defect that disappears when a debug print is added. Discuss causes (ordering, mutation during iteration, hidden dependency) and design a strategy to catch it.

  • **Output:** candidates: loop mutates the list it iterates; set iteration order; time-dependent state

Check yourself

Common misconceptions

  • Editing code before reproducing the defect - destroys the evidence.
  • Experiments ordered by suspicion rather than by cost.
  • 'Fixing' by deleting the failing feature (the defect remains, the symptom hides).
  • Declaring victory on one green test; neighbours must still pass.
