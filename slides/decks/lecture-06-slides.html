Key definitions

Key definitions

  • Trace table (state table) — one row per loop pass; one column per variable the loop reads or writes.
  • Loop condition — the boolean that decides whether another pass happens; it belongs in the table.
  • Off-by-one error — a loop that runs once too often or too few; two classic causes are boundary mix-ups (≤ vs <) and wrong initialisation.
  • Nested loop — a loop inside a loop; the inner loop runs fully for every outer pass.
  • Invariant (informal) — a statement that is true before and after every pass; why the loop's answer is right.
  • Termination — the proof a loop ends: name a quantity that strictly decreases (or increases) and is bounded.
Explain each in one breath; the cases will do the heavy lifting.
Worked example

Trace the tally: loop reasoning on paper

cs-021

Sum the numbers 1..12, skipping multiples of 3. Predict first, then trace the loop table.

Expected: 48

Cost: O(limit). Skipped items cost a condition check but no addition - skipping is not free.

Worked example

Nested loops, traced honestly

cs-023

With n = 4 rows and the rule 'star when column <= row else dot', what does the double loop print? Trace row 2 by hand.

count = 0
for row in range(4):
    for col in range(3):
        count += 1
print(count)

Expected: four lines: * then **. then ***.. then ****...

Cost: O(n^2) characters - the sum 1 + 3 + 5 + ... + (2n - 1) = n^2 is the doubling-grid fact from the lecture.

Case cs-024 · Advanced

The Off-By-One Museum

Three near-identical loops that each misbehave by one step. Diagnose each, fix minimally, and state the lesson each artefact teaches.

  • **Input:** three loops: (a) range(1, n) summing 1..n, (b) while i <= n: i += 2 summing 1..n, (c) i = n; while i > 0: i -= i // 4 + 1
  • **Output:** the diagnosis: (a) misses the last value n; (b) visits only odd i, so every even value is skipped; (c) terminates, with a step count that grows logarithmically
  • Solve for the worked instance first. Then ask what would change if one
  • number, name, or condition were replaced by something stranger.

Check yourself

Common misconceptions

  • Tracing in the head - the table exists precisely because heads lie.
  • Omitting the loop-condition column, then wondering why termination is unclear.
  • Fixing the condition when the bug is the initialisation (and vice versa).
  • Assuming nested loops always multiply costs - they do, but say it with the grid, not as a slogan.
