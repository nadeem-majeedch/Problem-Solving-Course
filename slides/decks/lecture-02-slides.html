Lecture 02 — Pseudocode as Precision

Learning objectives

  • Write pseudocode precise enough to translate mechanically
  • Express input, processing, output as named steps
  • Trace pseudocode by hand before trusting it

Case-based lecture: you attempt, we discuss, then we reveal.

Key definitions

Key definitions

  • Pseudocode — a structured half-way language between English and code: precise enough to trace, free of syntax detail.
  • Statement — one pseudocode line doing exactly one job (read, assign, decide, repeat, output).
  • SEQUENCE — statements executed one after another, top to bottom.
  • Selection — IF/ELSE - choose between two continuations based on a condition.
  • Iteration — WHILE (repeat while a condition holds) and FOR (repeat once per item or count).
  • State — the set of variable values a program holds at one moment.
Explain each in one breath; the cases will do the heavy lifting.
Worked example

Largest of three, at three precision levels

cs-005

Read three numbers; output the largest. Make the pseudocode precise enough that a classmate translates it without questions.

Expected: 12 (and 7 for the tie case)

Cost: n - 1 comparisons for n numbers; can 2 compares ever suffice for 3 numbers? (No - a pigeonhole argument students can find themselves.)

Worked example

Password rules: order of tests

cs-006

Password valid when: 8-12 characters, at least one digit, starts with a letter. Output exactly one message naming the FIRST failing rule.

Expected: four different messages for the four traces

Cost: O(length) for the digit scan; the rest constant.

Worked example

The vending machine as a state machine

cs-007

Pseudocode for buying a snack: insert coins until credit >= price, then vend and give change; refuse when sold out (before accepting money).

Expected: vend, change 0.20, stock 2 | sold out, coins returned (stock 0 case)

Cost: O(coins inserted). The real content is the state table: credit and stock per event.

Worked example

Shuffle with a no-adjacent-artist rule

cs-008

Playlist A(pop), B(pop), C(jazz), D(pop), E(jazz). Order all songs once so no two same-artist songs are adjacent; state the repair rule when impossible.

a, b, c = 7, 12, 9
best = a
if b > best:
    best = b
if c > best:
    best = c
print(best)

Expected: A, C, B, E, D

Cost: O(n) passes for the interleave; the feasibility bound is the intellectual content.

Check yourself

Common misconceptions

  • Pseudocode that is Python with the punctuation removed - no abstraction gained.
  • One line doing three jobs ('read and validate and loop') - untraceable by design.
  • Assignment read as equality: 'c <- c + 1' is an order, not a claim.
  • Tests written in a random order, producing messages that contradict the spec.
