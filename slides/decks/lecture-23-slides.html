Key definitions

Key definitions

  • Greedy choice — take the locally best option now and never reconsider it
  • Exchange argument — a proof that any optimal solution can be reshaped into the greedy one
  • Counterexample — a small input where a proposed rule gives a provably wrong answer
  • Overlapping subproblems — a recursive computation that recomputes the same smaller cases many times
  • Memoisation — cache each subproblem's answer the first time it is computed
  • Dynamic programming — solve every needed subproblem once, in an order that makes each answer ready when required
Explain each in one breath; the cases will do the heavy lifting.
Worked example

The Meeting Room Marathon: greedy by earliest end

cs-090

Meetings (9,10.5), (9.5,11), (11,12), (10.5,12.5). Book as many non-overlapping meetings as possible in one room.

meetings = [(9, 10.5), (9.5, 11), (11, 12), (10.5, 12.5)]
ms = sorted(meetings, key=lambda m: m[1])
taken = 0
last_end = float("-inf")
chosen = []
for s, e in ms:
    if s >= last_end:
        taken += 1
        last_end = e
        chosen.append((s, e))
print(taken, chosen)

Expected: 2 meetings: (9, 10.5) and (11, 12)

Cost: O(n log n) for the sort, O(n) for the sweep.

Worked example

The Tolerance Ladder: greedy that must be checked

cs-091

A tolerance budget of 10 units; items cost 4, 5, 6, 7. Maximise how many items fit - then find a cost profile where 'cheapest first' fails.

costs = [4, 5, 6, 7]
budget = 10
costs.sort()
taken = spent = 0
for c in costs:
    if spent + c <= budget:
        taken += 1
        spent += c
print(taken, spent, budget - spent)

Expected: 2 items (4 + 5), leftover 1 - optimal for count, NOT for leftover (4+6 fills exactly)

Cost: O(n log n) sort dominates; the check-for-counterexample habit costs nothing and saves wrong answers.

Worked example

The Budgeted Syllabus: dynamic programming on weight

cs-092

Topics with (hours, points): (3,60), (2,50), (4,80), (1,30). Study budget 5 hours; maximise total points (each topic taken at most once).

topics = [(3, 60), (2, 50), (4, 80), (1, 30)]
budget = 5
dp = [0] * (budget + 1)
for h, p in topics:
    for j in range(budget, h - 1, -1):
        dp[j] = max(dp[j], dp[j - h] + p)
print(dp[budget])

Expected: 110 points (topics (2,50) and (3,60))

Cost: O(items x budget) time and O(budget) space - the classic DP price, paid to buy optimality that greedy cannot guarantee here.

Check yourself

Common misconceptions

  • Assuming the greedy that works on one example is proven - exchange argument or counterexample, no exceptions.
  • Sorting by the wrong key: earliest start fails interval scheduling where earliest end succeeds.
  • Memoising without a base case - the cache never fills, the stack never unwinds.
  • Iterating the knapsack budget ascending with 0/1 items - that allows reusing an item twice.
