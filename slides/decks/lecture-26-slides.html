Key definitions

Key definitions

  • Frequency table — each distinct value listed with the number of times it occurs
  • Conditional probability — P(A given B) = the share of B-outcomes where A also happens
  • Independence — knowing B does not change P(A); the 2x2 table factors cleanly
  • Base rate — how common a condition is before any evidence; ignoring it misleads
  • Multiplication rule — P(A and B) = P(A) x P(B given A)
  • Complement rule — P(not A) = 1 - P(A); often the cheaper route
Explain each in one breath; the cases will do the heavy lifting.
Worked example

The Survey Skew: weighted averages and representativeness

cs-100

Sample: 8 first-years (avg mood 6), 2 third-years (avg mood 8). Overall average mood - naive or weighted, and which is right?

m1, n1 = 6.0, 8
m2, n2 = 8.0, 2
pooled = (n1 * m1 + n2 * m2) / (n1 + n2)
weighted = (m1 + m2) / 2
print(round(pooled, 2), round(weighted, 2))

Expected: pooled mean 6.4 (per respondent); cohort-balanced 7.0 (per cohort)

Cost: O(1) - the difficulty is conceptual, not computational.

Worked example

The Late Bus Frequency: histogram as a hypothesis test

cs-101

Minutes-late over 14 days: 2, 0, 5, 3, 0, 7, 4, 1, 2, 6, 3, 0, 9, 2. Build the frequency table. Is 'usually less than 3 minutes late' a fair claim?

delays = [2, 0, 5, 3, 0, 7, 4, 1, 2, 6, 3, 0, 9, 2]
freq = {}
for d in delays:
    freq[d] = freq.get(d, 0) + 1
under3 = sum(c for d, c in freq.items() if d < 3)
print(under3, len(delays), f"{under3 / len(delays):.0%}")

Expected: 7 of 14 days under 3 minutes - 50%, not 'usually'

Cost: O(n) tally + O(u) report; the histogram is one of the cheapest, most honest tools in the kit.

Worked example

The Double-Click Question: conditional counting

cs-102

Of 100 sessions: 40 were mobile, and 10 sessions double-clicked. 8 of the double-clicks were mobile. P(mobile | double-click) vs P(double-click | mobile) - compute both, and why do they differ?

overlap, n_double, n_mobile = 8, 10, 40
p_m_given_d = overlap / n_double
p_d_given_m = overlap / n_mobile
print(round(p_m_given_d, 2), round(p_d_given_m, 2))

Expected: P(mobile | double-click) = 0.8; P(double-click | mobile) = 0.2

Cost: O(1) after the table exists; building the 2x2 from raw events is O(n).

Case cs-103 · Intermediate

The Grid Decision Review

A rare-condition flagger: 99% accurate, 1-in-1000 prevalence. Compute the chance a flagged person actually has it. The counterintuitive base-rate classic.

  • **Input:** prevalence 1/1000; flagger: sensitivity 99%, false-positive rate 1%
  • **Output:** P(condition | flagged) = 0.99*0.001 / (0.99*0.001 + 0.01*0.999) ~ 9.0%

Check yourself

Common misconceptions

  • Swapping the conditioning: P(A|B) is not P(B|A) - same numerator, different denominator.
  • Ignoring base rates: '8 of 10 double-clicks are mobile' says little without mobile's overall share.
  • Reading 'usually' off a table without computing the exact fraction - 50% is a coin flip, not a habit.
  • Believing independence means 'no relationship in the sample' - it is a model claim, and samples wobble.
