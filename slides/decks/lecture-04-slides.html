Key definitions

Key definitions

  • Variable — a name bound to a value; reassignment re-binds the name, it does not change history.
  • Expression — a piece of Python that produces a value (`2 + 3 * 4`, `len(name)`).
  • Statement — an instruction (`x = 5`, `print(x)`) - note the difference from an expression.
  • Type — the kind of value: int, float, str (text), bool. `"3" + 4` fails because types disagree.
  • Type conversion — `int(...)`, `float(...)`, `str(...)` translate between kinds; `int("3.5")` fails.
  • List — an ordered, changeable sequence: `scores = [8, 6, 9]`; positions start at 0.
Explain each in one breath; the cases will do the heavy lifting.
Worked example

Echo with limits, translated from pseudocode

cs-013

Read lines until the sentinel 'done'; echo each line uppercased, but skip lines longer than 20 characters (count them instead).

lines = ["coffee", "x" * 21, "tea", "done", "late"]
skipped = 0
for line in lines:
    if line == "done":
        break
    if len(line) > 20:
        skipped += 1
    else:
        print(line.upper())
print(skipped)

Expected: COFFEE then 1

Cost: O(total input length). Python: `while True:` + `break` mirrors the flowchart's loop with two exits.

Worked example

Course list cleaner: first lists, first filters

cs-014

Given a list of course codes, remove empty strings and duplicates (keeping first occurrences), and report how many entries were dropped.

Expected: ['CS1', 'MA2'] 2

Cost: O(n^2) with the list-membership check; the set version (lecture 13) is O(n) - say so, then wait.

Worked example

The change maker: state and arithmetic

cs-015

Price 2.35. The customer pays with coins 1.00, 1.00, 0.50. Compute credit as coins arrive, then change as 20/10/5-cent breakdown.

Expected: credit 250, change 15 -> [10, 5]

Cost: O(coins + denominations). The greedy breakdown works for this coin system - lecture 23 returns to when greedy is trustworthy.

Worked example

The meeting scheduler: constraints first

cs-016

Place requests into 5 slots, 1 hour each, max 2 meetings per slot, respect 'not on Friday'. Print the schedule and the refused requests.

Expected: schedule slots 1-4 used; refused: [Friday request]

Cost: O(requests x slots). Greedy first-fit is fine here; question for fast finishers: when does first-fit waste capacity?

Check yourself

Common misconceptions

  • Adding a number to a string ('3' + 4) - types must agree, so convert first.
  • Forgetting input() returns strings and 'multiplying' text by accident.
  • Off-by-one on the last element (index n of an n-length list).
  • Using a variable before any assignment and expecting zero.
