Key definitions

Key definitions

  • Factorial — n! = n x (n-1) x ... x 1; the number of ways to arrange n items in order
  • Permutation — an ordered selection; order matters, so AB and BA are different
  • Combination — an unordered selection; order does not matter, so AB and BA are the same
  • Complement counting — count the opposite of what you want, then subtract from the total
  • Pigeonhole principle — if more than n items go into n boxes, some box holds two
  • Binomial coefficient — C(n, k) = n! / (k! (n-k)!); the number of k-sized teams from n people
Explain each in one breath; the cases will do the heavy lifting.
Worked example

The locker problem: divisors leave squares open

cs-057

100 lockers, 100 students; student i toggles every i-th locker. Which lockers end open?

open_lockers = [False] * 101
for student in range(1, 101):
    for locker in range(student, 101, student):
        open_lockers[locker] = not open_lockers[locker]
squares = [n for n in range(1, 101) if open_lockers[n]]
print(squares[:5], squares[-1], len(squares))

Expected: open lockers: 1, 4, 9, 16, 25, 36, 49, 64, 81, 100

Cost: Simulation O(n log n) (harmonic sum); the mathematical answer is O(1) - reasoning beats brute force.

Worked example

Team photo: count first, then block

cs-058

5 students line up for a photo; P and Q refuse to stand together. How many acceptable lineups?

import math
total = math.factorial(5)
blocked = math.factorial(4) * 2
print(total, blocked, total - blocked)

Expected: 72

Cost: O(1) with the counting argument; enumerating 120 lineups is fine too but does not scale.

Worked example

The committee draw: complements and stars

cs-059

A committee of 4 from 6 CS and 4 DS students. How many committees include at least one of each programme?

import math
c = math.comb
total = c(10, 4)
forbidden = c(6, 4) + c(4, 4)
print(total, forbidden, total - forbidden)

Expected: 194

Cost: O(1) arithmetic via factorials; a brute-force enumeration would touch all 210 committees.

Worked example

The birthday question: product of complements

cs-060

How many people are needed for a shared-birthday chance above 50%, assuming 365 equally likely days and no leap days?

p = 1.0
n = 0
while p >= 0.5:
    n += 1
    p *= (366 - n) / 365
print(n, round(1 - p, 3))

Expected: 23 people (P(shared) ~ 50.7%)

Cost: O(answer) for the product, O(trials x n) for the simulation - both trivial here.

Check yourself

Common misconceptions

  • Multiplying when you should add: 'and' stages multiply, 'or' cases add.
  • C(10,4) computed as 10x9x8x7 - the order of a chosen team was counted 4! times.
  • Applying complement counting with overlapping cases - subtraction needs disjoint sets.
  • Believing the pigeonhole principle needs large numbers - 3 socks, 2 colours is already enough.
