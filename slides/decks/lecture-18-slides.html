Key definitions

Key definitions

  • Stable sort — equal keys keep their original relative order - the property that makes sort-by-one-key-at-a-time compose.
  • Composite key — a tuple used as the sort key so ties break on later components.
  • Merge — combine two sorted lists into one in a single linear pass - the engine of merge sort.
  • Selection sort (idea) — repeatedly pick the smallest remaining element; O(n^2) comparisons regardless of input.
  • Insertion sort (idea) — grow a sorted prefix by sliding each new item left into place; fast on nearly-sorted data.
  • Comparison sort — any sort that only asks 'is a before b?'; log(n!) is its information-theoretic floor.
Explain each in one breath; the cases will do the heavy lifting.
Worked example

Rank the Leaderboard: sort with a two-part key

cs-069

Players: ada 90, bo 75, cy 90. Rank by score, highest first; ties broken alphabetically.

players = [("ada", 90), ("bo", 75), ("cy", 90)]
ranked = sorted(players, key=lambda p: (-p[1], p[0]))
print(ranked)

Expected: ada (90), cy (90), bo (75)

Cost: O(n log n) comparisons - the sorting cost dominates; the key is computed once per element.

Worked example

The Meeting Merge: the merge step by hand

cs-070

Two rooms' meeting start times are already sorted: 9, 10, 12 and 9.5, 11. Produce one sorted list.

a = [9, 10, 12]
b = [9.5, 11]
merged = []
i = j = 0
while i < len(a) and j < len(b):
    if a[i] <= b[j]:
        merged.append(a[i])
        i += 1
    else:
        merged.append(b[j])
        j += 1
merged.extend(a[i:])
merged.extend(b[j:])
print(merged)

Expected: 9, 9.5, 10, 11, 12

Cost: O(n + m) - linear in the output size; no element is compared twice.

Worked example

Closest Pair, Small n: brute force and its price

cs-071

Points (0,0), (3,4), (1,1). Which two are closest?

points = [(0, 0), (3, 4), (1, 1)]
best = None
for i in range(len(points)):
    for j in range(i + 1, len(points)):
        dx = points[i][0] - points[j][0]
        dy = points[i][1] - points[j][1]
        d = (dx * dx + dy * dy) ** 0.5
        if best is None or d < best[0]:
            best = (d, points[i], points[j])
print(best[1], best[2])

Expected: closest pair: (0, 0) and (1, 1)

Cost: O(n^2) pairs - fine for a classroom, hopeless for a million points; knowing WHERE the wall is, is the lecture's point.

Check yourself

Common misconceptions

  • Believing sorted() sorts in place - it returns a new list; the original is untouched.
  • Sorting by one key then overwriting with another, expecting both to apply - order of passes matters.
  • Assuming stability without checking the documented contract of the sort used.
  • Treating n log n vs n^2 as academic - on 100k items it is the difference between instant and minutes.
