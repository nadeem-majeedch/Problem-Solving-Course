# Activities — Instructor Notes (keys only, not published)

- **Pacing signal.** In every activity, watch the second minute: teams
  still writing after minute two are stuck on *understanding*, not
  speed. Announce "60 seconds, current state only" — the activity's
  purpose is process, not completion.
- **Board technique.** Relay and duel work best when you refuse to erase
  wrong answers; the debrief compares them. Wrong rankings are the
  lesson, not noise.
- **Selection guide.**
  - Think-Pair-Debug: use a bug from *last* lecture's family so it
    revisits without repeating.
  - Case Relay: pick the lecture's own family; do not run it on expert
    cases — the model step collapses.
  - Sketch That Flow: strongest in week 1–4; in later weeks use it as a
    remedial warm-up before recursion.
  - Complexity Duel: always include the constant-factor trap; without it
    the vote is boring.
- **Grouping.** Relay teams of 3–4; pairs for debug and flow. Rotate
  relays so the same team is not always last (they get the hardest
  inherited state).
