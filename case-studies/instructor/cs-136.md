## Reasoning walkthrough

**Worked instance.** Four study groups, five conflict pairs; slots are
colours; find the minimum slot count with a justified lower bound.

**Expected result.** demo prints `chromatic number 3 |
colouring {1: [G1, G4], 2: [G2], 3: [G3]} | LB: triangle G1-G2-G3` —
the minimum is 3 because G1, G2, G3 pairwise conflict (a triangle
needs three distinct slots); the displayed colouring achieves it.

**Method — graphs, scheduling, certificate of optimality.** Walk the
class through these moves:

1. Model first: groups are vertices, conflicts are edges. The
   timetable question becomes "how many colours for this graph?" —
   the modelling step does most of the work.
2. Lower bound from structure: {G1, G2, G3} pairwise conflict, so any
   timetable needs ≥ 3 slots — a certificate, not a hunch.
3. Achieve 3: check the edge list — G1 conflicts G2 and G3 only, so
   G1 and G4 may share a slot. Greedy in order G1, G2, G3, G4 with
   smallest legal colour: G1→1, G2→2, G3→3, G4→1. Every edge
   respected: 1−2, 1−3, 2−3, 2−4, 3−4 all differ.
4. Trade-off: fewest slots optimises the room's time, not people's —
   a group presenting in a packed slot may prefer more, smaller
   slots; name the stakeholder for whom "minimum" is wrong.

**Where this class gets stuck.** Students colour immediately and land
on 4 slots because greedy in an unlucky order wastes colours — the
triangle lower bound is the argument that stops the search. Second
stall: treating "minimum" as unproven; the triangle *is* the proof
for this instance.

## Five-minute teaching sequence

Minute 0–1 — **Read and analyse.** Expect the graph drawn. Watch for:
listing conflicts without drawing.
Minute 1–3 — **Develop an approach.** Expect the triangle found and a
3-slot attempt; a valid 3-colouring without the lower-bound argument
is partial credit.
Minute 3–5 — **Compare and write.** Expect the LB sentence and the
stakeholder trade-off drafted.
Reveal and discuss — keep the reveal inside 10 minutes so the exit question still fits.

## Difficulty adaptation

- **Simplify.** Three groups, two conflicts — ask for the model and a
  2-slot answer with its LB (an edge).
- **Extend.** Add G5 conflicting only with G1: the minimum stays 3
  (G5 joins slot 2 or 3); ask why adding a vertex did not raise the
  bound.
- **Hints (progressive).**
  1. *Re-orient:* "Find three groups where every pair conflicts."
  2. *Structure:* "Model, then lower bound, then colouring — in that
     order."
  3. *Near-answer:* the common wrong turn is trusting a greedy order
     to be minimal — undo that choice and re-derive the step it
     breaks.

## Reference solution (pseudocode)

```
V <- {G1..G4}; E <- conflict pairs
LB: G1,G2,G3 pairwise conflict -> answer >= 3
greedy colouring (order G1, G2, G3, G4; smallest legal colour):
    G1->1, G2->2, G3->3, G4->1
OUTPUT 3 with the colouring and the triangle LB
```

## Reference solution (Python)

```python
EDGES = [("G1", "G2"), ("G1", "G3"), ("G2", "G3"),
         ("G2", "G4"), ("G3", "G4")]
GROUPS = ["G1", "G2", "G3", "G4"]

def colour(order):
    assign = {}
    for v in order:
        used = set()
        for u, c in assign.items():
            if (u, v) in EDGES or (v, u) in EDGES:
                used.add(c)
        c = 1
        while c in used:
            c += 1
        assign[v] = c
    return assign

if __name__ == "__main__":
    a = colour(GROUPS)
    slots = {}
    for g, c in a.items():
        slots.setdefault(c, []).append(g)
    print("chromatic number", max(a.values()),
          "| colouring", dict(sorted(slots.items())),
          "| LB: triangle G1-G2-G3")
```

The code is runnable as-is; executing the file prints the worked instance
so you can demo it live on the projector.

## Edge cases

- No conflicts at all — one slot; the LB degenerates (no clique
  beyond a single vertex), colouring trivially 1.
- A complete graph K4 — four slots; the clique LB is tight.
- An isolated group (no edges) — shares any slot; the LB is
  unaffected.

## Alternative approaches

- Greedy in a different vertex order — can waste a colour; the fix is
  the lower-bound argument, not a better order hunt.
- Integer-programming formulation — exact and overkill; name it as
  the industrial version of this case.
- Constraint propagation over slots — instructive at this size;
  mention as the bridge to cs-120's constraint search.
- **Cost.** Greedy is O(V·E) per order; the real result is that a
  structural lower bound converts an optimisation into a check.

## Common pitfalls

- Colouring before drawing the graph.
- Claiming 3 without the triangle certificate.
- Assigning G4 to slot 2 or 3 (G4 conflicts both G2 and G3).
- Treating "fewest slots" as an objective-free choice.

## Reveal script

1. Display the case and start the timer (5 minutes). While students work,
   circulate and read shoulders; pick one conventional attempt and one
   surprising one for the board.
2. Ask first: "Which three groups pairwise conflict?"
3. Draw the graph on the board, mark the triangle, state the LB.
4. Surface the wrong turn directly: greedy-order obsession — the
   certificate, not the order, proves 3.
5. Show the reference Python, run it on the worked instance, and let the
   class compare with their own answers.
6. Close by naming the technique — "graph colouring with a structural
   lower bound" — and hand over the discussion prompt about G5.

## Assessment use

- **Formative use.** discussion-grade: mark the LB argument and the
  model before any colouring.
- **Mini-rubric (10 points).**
  - *Structure (2):* graph model drawn and named.
  - *Method (3):* triangle LB stated; colouring respects every edge.
  - *Result (3):* minimum 3 with certificate; G4 placed correctly.
  - *Communication (2):* trade-off names a stakeholder.
- **Follow-up check.** G5 conflicts only with G1: why can slot 2 or 3
  absorb G5, and why doesn't the LB move?
