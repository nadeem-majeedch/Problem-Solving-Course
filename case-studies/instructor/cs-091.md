## Reasoning walkthrough

**Worked instance.** scores [3, 1, 8, 2, 9, 4]

**Expected result.** LIS = [3, 8, 9] or [1, 8, 9] or [1, 2, 4] or [3, 4]... length 3; dp[i] = longest ending at i

**Method — recursion and dynamic programming.** Walk the class through these moves:

1. Define the subproblem in words (what does f(k) mean?).
2. Find the base case(s) — the smallest inputs answered directly.
3. Write the transition: how f(k) uses smaller answers.
4. Draw the call tree; memoise if subproblems repeat.

**Where this class gets stuck.** State: best[i] = longest increasing subsequence ENDING at i. Transition: best[i] = 1 + max(best[j] for j<i with a[j]<a[i]). Expect the first
five minutes to produce a missing or wrong base case = infinite recursion as the

## Reference solution (pseudocode)

FUNCTION lis(a)
    IF NOT a THEN
        RETURN (0, [])
    best <- [1] * LENGTH(a)
    prev <- [-1] * LENGTH(a)
    FOR EACH i IN range 0..LENGTH(a) DO
        FOR EACH j IN range 0..i DO
            IF (a[j] < a[i]) AND (best[j] + 1 > best[i]) THEN
                best[i] <- best[j] + 1
                prev[i] <- j
    k <- MAX(range 0..LENGTH(a); key = (i) -> best[i])
    seq <- []
    WHILE k != -1 DO
        append a[k] to seq
        k <- prev[k]
    RETURN (best[MAX(range 0..LENGTH(a); key = (i) -> best[i])], seq[.. by -1])
// demo run: OUTPUT lis([3, 1, 8, 2, 9, 4])


## Reference solution (Python)

```python
def lis(a):
    if not a:
        return 0, []
    best = [1] * len(a)
    prev = [-1] * len(a)
    for i in range(len(a)):
        for j in range(i):
            if a[j] < a[i] and best[j] + 1 > best[i]:
                best[i] = best[j] + 1
                prev[i] = j
    k = max(range(len(a)), key=lambda i: best[i])
    seq = []
    while k != -1:
        seq.append(a[k])
        k = prev[k]
    return best[max(range(len(a)), key=lambda i: best[i])], seq[::-1]

if __name__ == "__main__":
    print(lis([3, 1, 8, 2, 9, 4]))   # (3, one of the length-3 sequences)
```

## Edge cases

- Termination: name the update that guarantees the loop ends, and check it on the smallest input.
- Empty or single-item input: decide what is returned and what must NOT be printed.
- Degenerate values: zero, negatives, and duplicates among the instance's data.


## Alternative approaches

- State: best[i] = longest increasing subsequence ENDING at i. Transition: best[i] = 1 + max(best[j] for j<i with a[j]<a[i]).
- Iterative table versus recursive formulation: same recurrence, different order of filling it; the loop version cannot overflow any call stack.
- A table filled by hand before any code: for the size of instance here it is both a solution and the test oracle.
- **Cost.** Quadratic in the worst case: the nested passes revisit the data once per element; the alternatives shift exactly this cost.


## Common pitfalls

- A missing or wrong base case = infinite recursion.
- An update path that never moves the state — the loop that never ends; test on an interval of size two.
- Mutating the caller's list when the result was meant to be a fresh one — the demo where the input 'changes by itself'.
- Reporting the answer without the rule that produced it — the decision becomes uncheckable.
