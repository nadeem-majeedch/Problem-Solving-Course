## Reasoning walkthrough

**Worked instance.** 7 days, each day needs 2 staff; ada/bo/cy/dee available on subsets; max 4 days each

**Expected result.** a feasible rota or proof none exists (try greedy by most-constrained day first)

**Method — brute force and search spaces.** Walk the class through these moves:

1. Describe the search space precisely (what is one candidate?).
2. Count the space before enumerating it.
3. Enumerate systematically to avoid duplicates and gaps.
4. Filter with the constraint; prune what cannot succeed.

**Where this class gets stuck.** Cover the HARDEST days first (fewest available staff); if a day has zero candidates, report impossible immediately. Expect the first
five minutes to produce enumerating unordered items in every order (n! instead of c(n,k)) as the
most common wrong turn; plan the reveal around it.

## Reference solution (pseudocode)

FUNCTION rota(days, avail, max_days)
    load <- map{s: 0 for s in set{p for v in (avail values)}}
    assignment <- map{}
    FOR EACH d IN SORTED(avail; key = (d) -> LENGTH(avail[d])) DO
        candidates <- {s for each s in avail[d] AND load[s] < max_days}
        IF LENGTH(candidates) < 2 THEN
            RETURN (null, d)
        chosen <- SORTED(candidates)[..2]
        assignment[d] <- chosen
        FOR EACH s IN chosen DO
            load[s] <- load[s] + 1
    RETURN (assignment, null)
// demo run: OUTPUT rota(days, avail)


## Reference solution (Python)

```python
def rota(days, avail, max_days=4):
    # avail: dict day -> list of staff who can work it
    load = {s: 0 for s in {p for v in avail.values() for p in v}}
    assignment = {}
    for d in sorted(avail, key=lambda d: len(avail[d])):
        candidates = [s for s in avail[d] if load[s] < max_days]
        if len(candidates) < 2:
            return None, d
        chosen = sorted(candidates)[:2]
        assignment[d] = chosen
        for s in chosen:
            load[s] += 1
    return assignment, None

if __name__ == "__main__":
    days = ["mon", "tue", "wed"]
    avail = {"mon": ["ada", "bo", "cy"], "tue": ["bo"], "wed": ["cy", "dee", "ada", "bo"]}
    print(rota(days, avail))   # (None, 'tue') - impossible
```

## Edge cases

- First occurrence of a key not yet in the map — the default path must produce a defined answer.
- Ties: two equal values may swap order in the input; the stated rule must pin the output.
- Empty or single-item input: decide what is returned and what must NOT be printed.
- Degenerate values: zero, negatives, and duplicates among the instance's data.


## Alternative approaches

- Cover the HARDEST days first (fewest available staff); if a day has zero candidates, report impossible immediately.
- Loop-first formulation versus a comprehension/direct-expression formulation — same result, different emphasis on state versus intent.
- Sort first, then scan once, versus scanning with extra bookkeeping and no sort: the sort pays for itself only when later steps reuse the order.
- **Cost.** The sort dominates the cost: n log n in the input size, everything after it is one cheap pass; the alternatives shift exactly this cost.


## Common pitfalls

- Enumerating unordered items in every order (n! instead of c(n,k)).
- Reading a key before it exists (the first occurrence) instead of using the default path.
- Reporting the answer without the rule that produced it — the decision becomes uncheckable.


## Reveal script

1. Display the case and start the timer (5 minutes). While students work,
   circulate and read shoulders; pick one conventional attempt and one
   surprising one for the board.
2. Ask first: 'What is the search space, and in what order will you try it?'
3. Walk the worked instance (7 days, each day needs 2 staff; ada/bo/cy/dee available on subsets; max 4 days each) on the board
   under the stated rule before any code appears; the class calls the
   next state at each step.
4. Surface the wrong turn directly: 'enumerating unordered items in every order (n! instead of c(n,k))' — ask the room
   which quiet assumption it makes.
5. Show the reference Python, run it on the worked instance, and let the
   class compare with their own answers.
6. Close by naming the technique — "brute force and search spaces" — and hand over the
   discussion prompt: **"Double the input size: is this still acceptable? Show the arithmetic."**


## Assessment use

- **Formative use.** discussion-grade: mark assumption quality and rule precision rather than the final number, and expect the full cycle to run long.
- **Mini-rubric (10 points).**
  - *Structure (2):* inputs, outputs, and the binding constraint named before any computation.
  - *Method (3):* the stated moves executed — especially "Count the space before enumerating it"
    and "Enumerate systematically to avoid duplicates and gaps".
  - *Result (3):* the worked instance computed correctly (a feasible rota or proof none exists (try greedy by…),
    and the answer survives the smallest and the boundary input.
  - *Communication (2):* assumptions stated; the answer reports which rule produced it.
- **Follow-up check.** A key appears that was never seen before: which line of your rule handles it, and what does it output?
