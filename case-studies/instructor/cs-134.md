## Reasoning walkthrough

**Worked instance.** Twelve readings, window k = 3, flag when a value
exceeds the average of the previous three by more than 10.

**Expected result.** demo prints `flags at [4, 8] values [30, 45]` and
`day cost: A 4320 additions, B 1440 updates` — 30 beats its window
average 7 by 23, 45 beats its window average 10 by 35; no other minute
clears the bar. Method A re-adds k values per minute (1440 × 3);
method B updates its running sum once per minute.

**Method — algorithm selection, trade-offs, anomalies.** Walk the class
through these moves:

1. Boundary first: minutes 0–2 have no full window and are never
   flagged — write that rule before any loop.
2. Method A trace at index 3: window 5+6+7 = 18, average 6, 8−6 = 2 →
   no flag. Index 4: window 6+7+8 = 21, average 7, 30−7 = 23 → flag.
   Index 8: window 9+10+11 = 30, average 10, 45−10 = 35 → flag.
3. Cost arithmetic on real n: A does k additions per minute → 1440 × 3
   = 4320/day; B does one subtract + one add → 1440 updates/day. Same
   flags, three times the additions.
4. The ship decision is B *with* a drift test: B's state must equal
   the true window sum, so the one-line check is "recompute the window
   sum from scratch every m minutes and compare" — correctness
   monitoring bought with a fraction of A's cost.

**Where this class gets stuck.** Students compare "O(nk) vs O(n)" as
slogans and skip the counted arithmetic — make them multiply 1440 × 3.
The second stall is the window bookkeeping: after flagging index i,
the window advances by dropping `vals[i−k]` and adding `vals[i]`;
getting that transition wrong corrupts every later flag (have them
verify runsum = 30 at index 8).

## Five-minute teaching sequence

Minute 0–1 — **Read and analyse.** Expect the boundary rule and the
flag rule restated. Watch for: flagging minute 2 (no full window).
Minute 1–3 — **Develop an approach.** Expect flags 4 and 8 via method
A logic; a correct flag set with a cost guess is partial credit.
Watch for: including the current value in its own window.
Minute 3–5 — **Compare and write.** Expect the day-cost table and the
ship sentence; pairs defend B against the drift objection.
Reveal and discuss — keep the reveal inside 10 minutes so the exit question still fits.

## Difficulty adaptation

- **Simplify.** Eight readings, k = 2 — the trace shortens and the
  second flag still appears.
- **Extend.** Ask what k = 180 at n = 86,400 does to the counts
  (A: 15,552,000 additions; B: 86,400 updates) — the moment the
  "it's only 3×" intuition dies.
- **Hints (progressive).**
  1. *Re-orient:* "Which indices even have a full window?"
  2. *Structure:* "Advance the window by dropping one and adding one;
     write the two indices."
  3. *Near-answer:* the common wrong turn is window drift after a
     flag — undo that choice and re-derive the step it breaks.

## Reference solution (pseudocode)

```
runsum <- vals[0] + ... + vals[k-1]
FOR i FROM k TO n-1:
    IF vals[i] - runsum/k > thr THEN flag i
    runsum <- runsum + vals[i] - vals[i-k]
// method A: recompute runsum from the previous k values every i.
```

## Reference solution (Python)

```python
VALS = [5, 6, 7, 8, 30, 9, 10, 11, 45, 12, 13, 14]
K, THR = 3, 10

def flags(vals, k=K, thr=THR):
    out = []
    runsum = sum(vals[:k])
    for i in range(k, len(vals)):
        if vals[i] - runsum / k > thr:
            out.append(i)
        runsum += vals[i] - vals[i - k]
    return out

if __name__ == "__main__":
    f = flags(VALS)
    print("flags at", f, "values", [VALS[i] for i in f])
    n = 1440
    print(f"day cost: A {n * K} additions, B {n} updates")
```

The code is runnable as-is; executing the file prints the worked instance
so you can demo it live on the projector.

## Edge cases

- A spike in the first k minutes — never flagged (window rule); say so
  in the monitoring policy.
- k ≥ n — no index ever has a full window; the flag list is empty.
- Constant readings — runsum stays k×c, no flags; the cheapest sanity
  test for the deployed version.

## Alternative approaches

- Median-of-window instead of mean — robust to the spike polluting
  its own window; costs a sort per step, a real trade-off worth one
  sentence.
- Vectorised rolling mean (pandas-style) — faster constants, but the
  course's point is the *reasoning*, and the dependency is not needed
  to decide.
- Threshold on absolute change (difference of consecutive values) —
  different rule, different flags (only index 4); use it to show that
  "anomaly" is a defined quantity, not a vibe.
- **Cost.** B is O(n) vs A's O(nk); the drift check adds O(n/m) —
  still linear, still cheap, and it converts a correctness risk into a
  monitored invariant.

## Common pitfalls

- Including the current reading in its own window.
- Forgetting the drop-value `vals[i-k]` after a flag.
- Choosing B "because O(1)" without counting the day's operations.
- Shipping B with no drift test — silent state corruption.

## Reveal script

1. Display the case and start the timer (5 minutes). While students work,
   circulate and read shoulders; pick one conventional attempt and one
   surprising one for the board.
2. Ask first: "Which minutes are even eligible for flagging?"
3. Walk method A's trace at indices 3, 4, 8 on the board; the room
   computes each window.
4. Surface the wrong turn directly: window drift after a flag — ask
   what runsum must equal at index 8 and verify (30).
5. Show the reference Python, run it on the worked instance, and let the
   class compare with their own answers.
6. Close by naming the technique — "running-sum window with a drift
   invariant" — and hand over the discussion prompt about per-second
   data.

## Assessment use

- **Formative use.** discussion-grade: mark cost arithmetic and
  boundary handling over the flag list alone.
- **Mini-rubric (10 points).**
  - *Structure (2):* window rule and boundary stated before tracing.
  - *Method (3):* flags derived from A's logic; costs counted on real n.
  - *Result (3):* flags 4 and 8 (30, 45); 4320 vs 1440 with units.
  - *Communication (2):* ship decision names the drift safeguard.
- **Follow-up check.** Two spikes one minute apart: does the second
  spike's window contain the first, and what does that do to the
  average?
