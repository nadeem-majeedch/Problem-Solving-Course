## Reasoning walkthrough

**Worked instance.** 6 CS, 4 DS; committee of 4 with at least one of each programme

**Expected result.** total C(10,4)=210; all-CS C(6,4)=15; all-DS C(4,4)=1; valid 210-16 = 194

**Method — counting and probability.** Walk the class through these moves:

1. Frame the question: how many outcomes, and how many favourable?
2. Decide ordered vs unordered, with vs without replacement — in words first.
3. Compute with the multiplication/addition principles (or complements).
4. Check the count by brute-force enumeration when small.

**Where this class gets stuck.** Complement again: 'at least one of each' = total minus 'single-programme only'. Expect the first
five minutes to produce adding situations that multiply (wearing a shirt and trousers) as the
most common wrong turn; plan the reveal around it.


## Five-minute teaching sequence

Minute 0–1 — **Read and analyse.** Expect inputs, outputs, and at least
one stated assumption named; the deciding quantity here is the input
rule. Watch for: retelling the story without extracting the decision.
Minute 1–3 — **Develop an approach.** Expect a rule or a first-step
computation on the instance; a correct rule with an arithmetic slip is
partial credit. Watch for: a rule that reads correctly but computes on the wrong quantity in the input data.
Minute 3–5 — **Compare and write.** Expect the update rule or loop
skeleton written down, pairs comparing orders of operations. If most
pairs stall, give the structure hint from the difficulty ladder
(below) whole-class rather than pair by pair.
Reveal and discuss — keep the reveal inside 10 minutes so the exit question still fits.

## Reference solution (Python)

```python
from math import comb

def committees():
    total = comb(10, 4)
    invalid = comb(6, 4) + comb(4, 4)
    return total - invalid

if __name__ == "__main__":
    print(committees())   # 194
```

## Reveal script

1. Display the case and start the timer (5 minutes). While students work,
   circulate and read shoulders; pick one conventional attempt and one
   surprising one for the board.
2. Ask first: 'Are you counting arrangements, selections, or successes — and does order matter here?'
3. Walk the worked instance (6 CS, 4 DS; committee of 4 with at least one of each programme) on the board
   under the stated rule before any code appears; the class calls the
   next state at each step.
4. Surface the wrong turn directly: 'adding situations that multiply (wearing a shirt and trousers)' — ask the room
   which quiet assumption it makes.
5. Show the reference Python, run it on the worked instance, and let the
   class compare with their own answers.
6. Close by naming the technique — "counting and probability" — and hand over the
   discussion prompt: **"When is enumeration a legitimate answer rather than a crutch?"**
