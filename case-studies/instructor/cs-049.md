## Reasoning walkthrough

**Worked instance.** "the cat the dog the bird cat"

**Expected result.** the:3, cat:2, dog:1, bird:1 -> top three: the(3), cat(2), then dog and bird tie at 1 (tie-break: alphabetical)

**Method — mappings and sets.** Walk the class through these moves:

1. Choose the key: what identifies an item uniquely?
2. Choose the value: a count, a list, or a marker.
3. Handle the missing-key path explicitly (get/first insert).
4. For sets: state what membership and uniqueness mean here.

**Where this class gets stuck.** Count with a dict; when reporting top-k, ties must be broken by a stated rule. Expect the first
five minutes to produce reading a missing key raises keyerror — use a default or check first as the
most common wrong turn; plan the reveal around it.


## Five-minute teaching sequence

Minute 0–1 — **Read and analyse.** Expect inputs, outputs, and at least
one stated assumption named; the deciding quantity here is the input
rule. Watch for: retelling the story without extracting the decision.
Minute 1–3 — **Develop an approach.** Expect a rule or a first-step
computation on the instance; a correct rule with an arithmetic slip is
partial credit. Watch for: reading an input key before it exists — the first occurrence needs the default path.
Minute 3–5 — **Compare and write.** Expect the update rule or loop
skeleton written down, pairs comparing orders of operations. If most
pairs stall, give the structure hint from the difficulty ladder
(below) whole-class rather than pair by pair.
Reveal and discuss — keep the reveal inside 10 minutes so the exit question still fits.

## Reference solution (pseudocode)

FUNCTION word_tally(text, k)
    counts <- map{}
    FOR EACH w IN (text split into words) DO
        counts[w] <- counts.get(w, default 0) + 1
    ranked <- SORTED((counts items); key = (kv) -> (-kv[1], kv[0]))
    RETURN ranked[..k]
// demo run: OUTPUT word_tally('the cat the dog the bird cat')


## Reference solution (Python)

```python
def word_tally(text, k=3):
    counts = {}
    for w in text.split():
        counts[w] = counts.get(w, 0) + 1
    ranked = sorted(counts.items(), key=lambda kv: (-kv[1], kv[0]))
    return ranked[:k]

if __name__ == "__main__":
    print(word_tally("the cat the dog the bird cat"))
```

## Edge cases

- First occurrence of a key not yet in the map — the default path must produce a defined answer.
- Ties: two equal values may swap order in the input; the stated rule must pin the output.
- Empty or single-item input: decide what is returned and what must NOT be printed.
- Degenerate values: zero, negatives, and duplicates among the instance's data.


## Alternative approaches

- Count with a dict; when reporting top-k, ties must be broken by a stated rule.
- Loop-first formulation versus a comprehension/direct-expression formulation — same result, different emphasis on state versus intent.
- Sort first, then scan once, versus scanning with extra bookkeeping and no sort: the sort pays for itself only when later steps reuse the order.
- **Cost.** The sort dominates the cost: n log n in the input size, everything after it is one cheap pass; the alternatives shift exactly this cost.


## Common pitfalls

- Reading a missing key raises keyerror — use a default or check first.
- Reading a key before it exists (the first occurrence) instead of using the default path.
- Reporting the answer without the rule that produced it — the decision becomes uncheckable.


## Reveal script

1. Display the case and start the timer (5 minutes). While students work,
   circulate and read shoulders; pick one conventional attempt and one
   surprising one for the board.
2. Ask first: 'What is the key, and what belongs to its value — a membership fact or a running total?'
3. Walk the worked instance ("the cat the dog the bird cat") on the board
   under the stated rule before any code appears; the class calls the
   next state at each step.
4. Surface the wrong turn directly: 'reading a missing key raises keyerror — use a default or check first' — ask the room
   which quiet assumption it makes.
5. Show the reference Python, run it on the worked instance, and let the
   class compare with their own answers.
6. Close by naming the technique — "mappings and sets" — and hand over the
   discussion prompt: **"Re-derive the tie-break rule: is it a technicality or part of the specification?"**


## Assessment use

- **Formative use.** discussion-grade: mark assumption quality and rule precision rather than the final number, and expect the full cycle to run long.
- **Mini-rubric (10 points).**
  - *Structure (2):* inputs, outputs, and the binding constraint named before any computation.
  - *Method (3):* the stated moves executed — especially "Choose the value: a count, a list, or a marker"
    and "Handle the missing-key path explicitly (get/first insert)".
  - *Result (3):* the worked instance computed correctly (the:3, cat:2, dog:1, bird:1 -> top three: the(3), cat(2), then…),
    and the answer survives the smallest and the boundary input.
  - *Communication (2):* assumptions stated; the answer reports which rule produced it.
- **Follow-up check.** A key appears that was never seen before: which line of your rule handles it, and what does it output?
