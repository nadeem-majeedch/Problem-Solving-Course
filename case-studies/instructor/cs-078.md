## Reasoning walkthrough

**Worked instance.** perfect numbers below 10000 (sum of proper divisors equals n): 6, 28, 496, 8128

**Expected result.** demo prints [6, 28, 496, 8128] — the four perfect numbers below 10000; divisor bound sqrt(n) turns the naive O(n^2) sweep into ~O(n sqrt n)

**Method — brute force and search spaces.** Walk the class through these moves:

1. Describe the search space precisely (what is one candidate?).
2. Count the space before enumerating it.
3. Enumerate systematically to avoid duplicates and gaps.
4. Filter with the constraint; prune what cannot succeed.

**Where this class gets stuck.** Divisors pair around sqrt(n); check d and n/d together - one loop to the square root. Expect the first
five minutes to produce enumerating unordered items in every order (n! instead of c(n,k)) as the
most common wrong turn; plan the reveal around it.

## Reference solution (pseudocode)

FUNCTION perfects(limit)
    out <- []
    FOR EACH n IN range 2..limit DO
        s <- 1
        d <- 2
        WHILE d * d <= n DO
            IF n mod d = 0 THEN
                s <- s + d
                IF d != n div d THEN
                    s <- s + n div d
            d <- d + 1
        IF s = n THEN
            append n to out
    RETURN out
// demo run: OUTPUT perfects(10000)


## Reference solution (Python)

```python
def perfects(limit):
    out = []
    for n in range(2, limit):
        s = 1
        d = 2
        while d * d <= n:
            if n % d == 0:
                s += d
                if d != n // d:
                    s += n // d
            d += 1
        if s == n:
            out.append(n)
    return out

if __name__ == "__main__":
    print(perfects(10000))   # [6, 28, 496, 8128]
```

## Edge cases

- Termination: name the update that guarantees the loop ends, and check it on the smallest input.
- Empty or single-item input: decide what is returned and what must NOT be printed.
- Degenerate values: zero, negatives, and duplicates among the instance's data.


## Alternative approaches

- Divisors pair around sqrt(n); check d and n/d together - one loop to the square root.
- Rewrite the while-loop as a bounded for-loop over the data (or vice versa) and compare which version makes termination obvious.
- A table filled by hand before any code: for the size of instance here it is both a solution and the test oracle.
- **Cost.** Linear: one visit per item, a constant amount of work per visit; the alternatives shift exactly this cost.


## Common pitfalls

- Enumerating unordered items in every order (n! instead of c(n,k)).
- An update path that never moves the state — the loop that never ends; test on an interval of size two.
- Mutating the caller's list when the result was meant to be a fresh one — the demo where the input 'changes by itself'.
- Reporting the answer without the rule that produced it — the decision becomes uncheckable.
