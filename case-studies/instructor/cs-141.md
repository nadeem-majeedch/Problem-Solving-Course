## Reasoning walkthrough

**Worked instance.** A deployed refund rule with thresholds at 15 and
60 minutes, fed by a monitor that samples every five minutes; the
audience knows none of this.

**Expected result.** demo prints five boundary rows: a 13-minute
outage recorded as 15 and refunded 0.50, a 59-minute outage recorded
as 60 and refunded 2.00 — near the thresholds, the sampling quanta
decide the refund, not the true clock. That table *is* the memo's
honesty sentence, made concrete.

**Model memo (six sentences, teach this shape):**

1. Print credit is refunded automatically when the campus printing
   service is unavailable: 0.50 for outages of 15 minutes or more,
   2.00 for outages of an hour or more.
2. Outage length is measured by a monitor that checks every five
   minutes, so a 13-minute outage can be recorded as 15 — near the
   thresholds, the recorded time decides, and it can differ from the
   true time by up to five minutes.
3. Shorter outages receive no refund by design.
4. The thresholds (15 and 60 minutes) and the amounts (0.50 and 2.00)
   are policy choices, not technical facts.
5. You own those choices; the script only applies them.
6. If you want the boundaries moved or the amounts changed, say so and
   we will redeploy — nothing else in the refund logic would change.

**Method — communication, stakeholders, requirements.** Walk the class
through these moves:

1. Inventory every number in the script (2.00, 60, 0.50, 15, the
   5-minute quantum) and decide, for each, whether the manager must
   know it to act — that filter builds sentence 1–4.
2. Separate *mechanism* (sampling, thresholds) from *policy* (the
   choices): the memo hands policy back to its owner (sentence 4–5).
3. Write the honesty sentence from the boundary table: one sentence,
   no probability theory, no hedging — "recorded time can differ from
   true time by up to five minutes."
4. Cut ruthlessly: no architecture, no code, no apology — six
   sentences that survive a one-minute read.

**Where this class gets stuck.** Students either dump every technical
detail (a spec, not a memo) or strip the sampling fact (a dishonest
memo). The boundary demo resolves the argument: show the 13-minute
row and ask whether the manager can sign refunds without knowing it.

## Five-minute teaching sequence

Minute 0–1 — **Read and analyse.** Expect the two audiences separated
(decision-maker vs archive). Watch for: memos that explain the code
instead of the rule.
Minute 1–3 — **Develop an approach.** Expect a draft with the rule in
plain language; a draft missing the sampling caveat is partial credit.
Watch for: thresholds described as automatic facts.
Minute 3–5 — **Compare and write.** Expect the honesty sentence placed
and the policy sentence added; pairs count sentences (max six).
Reveal and discuss — keep the reveal inside 10 minutes so the exit question still fits.

## Difficulty adaptation

- **Simplify.** Give the six-sentence skeleton with blanks at the
  numbers; students fill and polish.
- **Extend.** Add the student-newspaper audience: which sentence
  survives unchanged, and which needs a second honest phrasing?
- **Hints (progressive).**
  1. *Re-orient:* "Underline every number in the script; each one
     needs a decision about whether it reaches the memo."
  2. *Structure:* "Rule, caveat, policy — three moves, six
     sentences."
  3. *Near-answer:* the common wrong turn is omitting the sampling
     quantum — undo that choice and re-derive the sentence it breaks.

## Reference solution (pseudocode)

```
recorded(m) <- round(m / STEP) * STEP        // the monitor's quanta
refund(r)   <- 2.00 IF r >= 60 ELSE 0.50 IF r >= 15 ELSE 0
demo: print true, recorded, refund for boundary cases
// the memo: rule in plain language + sampling caveat + policy hand-back
```

## Reference solution (Python)

```python
STEP = 5                      # monitor samples every five minutes

def recorded(minutes):
    return round(minutes / STEP) * STEP

def refund(recorded_min):
    if recorded_min >= 60:
        return 2.00
    if recorded_min >= 15:
        return 0.50
    return 0.00

if __name__ == "__main__":
    for true in (13, 14, 16, 59, 61):
        rec = recorded(true)
        print(f"true {true:2d} min -> recorded {rec:2d}"
              f" -> refund {refund(rec):.2f}")
```

The code is runnable as-is; executing the file prints the worked instance
so you can demo it live on the projector.

## Edge cases

- An outage of exactly 15 or 60 *true* minutes recorded one quantum
  short — the rule's `>=` boundary meets the sampler's rounding; say
  which side each lands on.
- Monitoring downtime during the outage (the monitor itself fails) —
  the recorded time understates; out of scope but worth one sentence
  in the memo's caveat if asked.
- A refund run on partial data (monitor outage) — policy for
  reprocessing belongs to the manager, sentence 5's territory.

## Alternative approaches

- A table of examples instead of the caveat sentence — concrete but
  open-ended; the sentence generalises, the table illustrates (use
  both in the reveal, the sentence in the memo).
- One memo per audience (manager vs students) — cleaner per reader,
  double the maintenance; the extension challenge explores it.
- Push the sampling fix instead of documenting it (store true
  start/end) — the real engineering answer; out of scope for a memo
  about the deployed system, name it in discussion.
- **Cost.** The memo costs six sentences now; omitting the caveat
  costs a dispute later — the cheapest honesty on campus.

## Common pitfalls

- Explaining implementation instead of the rule.
- Dropping the sampling caveat as "too technical".
- Presenting thresholds as immutable facts (they are policy).
- Exceeding six sentences — every clause must earn its place.

## Reveal script

1. Display the case and start the timer (5 minutes). While students work,
   circulate and read shoulders; pick one conventional attempt and one
   surprising one for the board.
2. Ask first: "Which numbers in the script must the manager know to
   act?"
3. Run the boundary demo; the 13-minute row lands the caveat debate.
4. Surface the wrong turn directly: the memo without the sampling
   sentence — ask what the manager would promise in a dispute.
5. Workshop one student memo against the six-sentence budget; show the
   model memo.
6. Close by naming the technique — "mechanism vs policy in plain
   language" — and hand over the discussion prompt about the
   blanket-refund reply.

## Assessment use

- **Formative use.** discussion-grade: mark honesty (the caveat) and
  decision-usefulness over prose style.
- **Mini-rubric (10 points).**
  - *Structure (2):* rule, caveat, policy all present within six
    sentences.
  - *Method (3):* every threshold translated; sampling named with its
    quantum.
  - *Result (3):* memo a non-technical manager can act on in one
    minute; no false claims near boundaries.
  - *Communication (2):* no jargon; policy ownership handed back.
- **Follow-up check.** The manager asks "could someone get a refund
  they shouldn't?" — which sentence answers, and is the answer yes?
