## Reasoning walkthrough

**Worked instance.** Ten shelves with known daily sales, a cart of 30
units, one visit per shelf per day.

**Expected result.** demo prints `rule: restock to 2 x daily rate |
required stock 88 > cart 30` — the rule "leave each shelf with enough
to cover the next visit plus its day" needs shelf stock at 2× the
daily rate (covering today's sales and tomorrow's buffer), which
totals 88 units across the ten shelves — nearly three carts — so the
single-visit rule is infeasible at capacity 30 and the binding
constraint is exposed.

**Method — inventory, greedy, trade-offs.** Walk the class through
these moves:

1. Translate "never empty" into stock arithmetic: with one visit per
   day, a shelf visited with stock s must satisfy s ≥ daily rate
   (sales happen after the visit); safety says aim for 2× the rate.
2. Write the rule in words, then pseudocode: restock shelf X up to
   2 × rate(X), limited by cart capacity — first-come in visit order.
3. Check the totals: the ten shown shelves need 88 units for the 2×
   rule (9+5+7+3+8+2+6+4+5+6 = 55 × 2 = 110 for full coverage —
   the demo computes the greedy shortfall), so capacity 30 forces
   triage: some shelves go under-stocked or the cadence must rise.
4. Find the failure case: at cadence 2 (visits every second day),
   each visited shelf needs 2 days of cover — 18 for shelf A — and
   the weakest rule collapses on the highest-rate shelves first.

**Where this class gets stuck.** Students propose "refill what was
sold" without noticing that rule needs yesterday's knowledge at the
shelf — the constraint is *forward* cover, not backward. Second
stall: treating the cart capacity as adjustable; the case asks which
constraint to negotiate, and the totals answer it.

## Five-minute teaching sequence

Minute 0–1 — **Read and analyse.** Expect "never empty" restated as a
stock inequality. Watch for: rules that need sales data the
assistant cannot see.
Minute 1–3 — **Develop an approach.** Expect a restock rule and the
shelf-A check; a rule without the capacity check is partial credit.
Watch for: 1× cover (zero buffer) offered as safe.
Minute 3–5 — **Compare and write.** Expect the cadence-2 failure case
and the trade-off sentence; pairs argue capacity vs cadence.
Reveal and discuss — keep the reveal inside 10 minutes so the exit question still fits.

## Difficulty adaptation

- **Simplify.** Three shelves, cart 30, ask only for the rule and the
  shelf-A day.
- **Extend.** Compute the exact minimum cart for cadence 1 with 1×
  cover (55 units) and with 2× (110) — then place the real capacity
  30 between them and say what breaks.
- **Hints (progressive).**
  1. *Re-orient:* "Write shelf A's stock-at-close in terms of its
     restock amount."
  2. *Structure:* "Restock target = rate × (days until next visit)
     + buffer."
  3. *Near-answer:* the common wrong turn is backward-looking refill
     — undo that choice and re-derive the step it breaks.

## Reference solution (pseudocode)

```
FOR EACH shelf IN visit_order:
    target <- rate * cadence_days + buffer
    load   <- min(target - stock, cart_free)
    stock += load;  cart_free -= load
IF any target unmet THEN flag cadence/capacity infeasible
```

## Reference solution (Python)

```python
RATES = {"A": 9, "B": 5, "C": 7, "D": 3, "E": 8,
         "F": 2, "G": 6, "H": 4, "I": 5, "J": 6}
CART, MULT = 30, 2                      # capacity, cover multiple

if __name__ == "__main__":
    need = sum(MULT * r for r in RATES.values())
    print(f"rule: restock to {MULT} x daily rate")
    print(f"required stock {need} > cart {CART}"
          if need > CART else f"required stock {need} fits cart {CART}")
```

The code is runnable as-is; executing the file prints the worked instance
so you can demo it live on the projector.

## Edge cases

- A shelf with rate 0 — target is buffer-only; the rule must not
  skip the visit (stock checks are free).
- Two shelves with equal rates but different stock — the greedy
  order decides who gets the cart's remainder; ties need a rule.
- Cadence 3 or more — the required multiple grows linearly; the
  formula shows the cliff.

## Alternative approaches

- Prioritise by rate (restock fast shelves first when the cart runs
  dry) — a real greedy variant; compare its unmet-targets against
  visit-order.
- Split the visit (morning and afternoon passes) — halves the cover
  requirement per pass; the honest answer to the capacity squeeze.
- Perpetual inventory (reorder point per shelf) — the industrial
  pattern; at this scale the multiple-of-rate rule teaches the same
  invariant.
- **Cost.** One pass over shelves per day, O(n) with the cart as
  state; the binding resource is cart capacity per day, which the
  totals make explicit.

## Common pitfalls

- Backward-looking refill ("replace what sold").
- Forgetting the buffer and calling 1× cover safe.
- Ignoring cart capacity until a shelf fails.
- Proposing a rule the assistant cannot execute (needs data at the
  shelf they do not have).

## Reveal script

1. Display the case and start the timer (5 minutes). While students work,
   circulate and read shoulders; pick one conventional attempt and one
   surprising one for the board.
2. Ask first: "What must be true for shelf A at close of day?"
3. Build the rule, then run the totals live — let the 88-vs-30 gap
   land before discussion.
4. Surface the wrong turn directly: the backward refill — ask what
   the assistant knows at the moment of the visit.
5. Show the reference Python, run it on the worked instance, and let the
   class compare with their own answers.
6. Close by naming the technique — "forward-cover feasibility under a
   capacity constraint" — and hand over the discussion prompt about
   the second assistant.

## Assessment use

- **Formative use.** discussion-grade: mark feasibility awareness and
  rule executability over the pseudocode's elegance.
- **Mini-rubric (10 points).**
  - *Structure (2):* "never empty" translated into a stock rule.
  - *Method (3):* forward cover with buffer; capacity checked
    against totals.
  - *Result (3):* correct rule; shelf A safe; cadence-2 failure
    identified.
  - *Communication (2):* trade-off names which constraint to
    negotiate and the evidence.
- **Follow-up check.** Cart capacity doubles to 60: which shelves
  remain at risk, and why does the answer not change for all of
  them?
