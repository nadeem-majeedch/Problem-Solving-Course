## Reasoning walkthrough

**Worked instance.** sorted [1, 2, 4, 7, 11], target 15 -> 4+11; target 20 -> none

**Expected result.** pair found (indices 3,4); none for 20; movement rule: sum small -> left++, sum big -> right--

**Method — invariants and two pointers.** Walk the class through these moves:

1. Define the pointers and the region each is responsible for.
2. State the invariant in one sentence: what is always true?
3. Derive the movement rule from the invariant — never memorise it.
4. Argue termination: what strictly shrinks every iteration?

**Where this class gets stuck.** Invariant: the answer pair, if it exists, always lies inside [l, r]. Each step discards one element safely. Expect the first
five minutes to produce moving both pointers on a branch that should move one as the
most common wrong turn; plan the reveal around it.

## Reference solution (pseudocode)

FUNCTION pair_sum(a, target)
    (l, r) <- (0, LENGTH(a) - 1)
    WHILE l < r DO
        s <- a[l] + a[r]
        IF s = target THEN
            RETURN (l, r)
        IF s < target THEN
            l <- l + 1
        ELSE
            r <- r - 1
    RETURN null
// demo run: OUTPUT pair_sum([1, 2, 4, 7, 11], 15)
// demo run: OUTPUT pair_sum([1, 2, 4, 7, 11], 20)


## Reference solution (Python)

```python
def pair_sum(a, target):
    l, r = 0, len(a) - 1
    while l < r:
        s = a[l] + a[r]
        if s == target:
            return l, r
        if s < target:
            l += 1
        else:
            r -= 1
    return None

if __name__ == "__main__":
    print(pair_sum([1, 2, 4, 7, 11], 15))   # (3, 4)
    print(pair_sum([1, 2, 4, 7, 11], 20))   # None
```

## Edge cases

- Termination: name the update that guarantees the loop ends, and check it on the smallest input.
- Empty or single-item input: decide what is returned and what must NOT be printed.
- Degenerate values: zero, negatives, and duplicates among the instance's data.


## Alternative approaches

- Invariant: the answer pair, if it exists, always lies inside [l, r]. Each step discards one element safely.
- Rewrite the while-loop as a bounded for-loop over the data (or vice versa) and compare which version makes termination obvious.
- A table filled by hand before any code: for the size of instance here it is both a solution and the test oracle.


## Common pitfalls

- Moving both pointers on a branch that should move one.
- An update path that never moves the state — the loop that never ends; test on an interval of size two.
- Reporting the answer without the rule that produced it — the decision becomes uncheckable.
