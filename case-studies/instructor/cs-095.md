**Expected result.** order: CS1, Stats, CS2, DS2, AI (or CS1, CS2, Stats, DS2, AI); cycle -> impossible

**Method — graphs and traversal.** Walk the class through these moves:

1. Model first: what are the nodes, what are the edges?
2. Choose the representation (adjacency list for sparse graphs).
3. Traverse with the right discipline: BFS for fewest steps, DFS for structure.
4. Keep a visited set — the difference between an algorithm and an infinite loop.

## Reference solution (pseudocode)

FUNCTION topo_order(nodes, prereqs)
    indeg <- map{n: 0 for n in nodes}
    dependents <- map{n: [] for n in nodes}
    FOR EACH (course, pres) IN (prereqs items) DO
        FOR EACH p IN pres DO
            append course to dependents[p]
            indeg[course] <- indeg[course] + 1
    ready <- SORTED({n for each n in nodes AND indeg[n] = 0})
    order <- []
    WHILE ready DO
        n <- ready.pop(0)
        append n to order
        FOR EACH m IN dependents[n] DO
            indeg[m] <- indeg[m] - 1
            IF indeg[m] = 0 THEN
                append m to ready
                ready.sort()
    IF LENGTH(order) != LENGTH(nodes) THEN
        RETURN null
    RETURN order
// demo run: OUTPUT topo_order(nodes, prereqs)


## Reference solution (Python)

```python
def topo_order(nodes, prereqs):
    indeg = {n: 0 for n in nodes}
    dependents = {n: [] for n in nodes}
    for course, pres in prereqs.items():
        for p in pres:
            dependents[p].append(course)
            indeg[course] += 1
    ready = sorted(n for n in nodes if indeg[n] == 0)
    order = []
    while ready:
        n = ready.pop(0)
        order.append(n)
        for m in dependents[n]:
            indeg[m] -= 1
            if indeg[m] == 0:
                ready.append(m)
                ready.sort()
    if len(order) != len(nodes):
        return None  # cycle
    return order
```

## Edge cases

- Termination: name the update that guarantees the loop ends, and check it on the smallest input.
- First occurrence of a key not yet in the map — the default path must produce a defined answer.
- Ties: two equal values may swap order in the input; the stated rule must pin the output.
- Empty or single-item input: decide what is returned and what must NOT be printed.
- Degenerate values: zero, negatives, and duplicates among the instance's data.


## Alternative approaches

- Kahn's algorithm: repeatedly take a course with no remaining prerequisites; if you get stuck, there is a cycle.
- Rewrite the while-loop as a bounded for-loop over the data (or vice versa) and compare which version makes termination obvious.
- Sort first, then scan once, versus scanning with extra bookkeeping and no sort: the sort pays for itself only when later steps reuse the order.
- **Cost.** The sort dominates the cost: n log n in the input size, everything after it is one cheap pass; the alternatives shift exactly this cost.


## Common pitfalls

- Forgetting the visited set on graphs with cycles.
- An update path that never moves the state — the loop that never ends; test on an interval of size two.
- Reading a key before it exists (the first occurrence) instead of using the default path.
- Mutating the caller's list when the result was meant to be a fresh one — the demo where the input 'changes by itself'.
- Reporting the answer without the rule that produced it — the decision becomes uncheckable.
