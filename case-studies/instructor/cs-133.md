## Reasoning walkthrough

**Worked instance.** Loop legs 4+6+7+8 = 25 minutes; two buses; depot
slots every ten minutes at :00–:50.

**Expected result.** demo prints `departures [0, 10, 25, 35, 50, 60]
gaps [10, 15, 10, 15, 10]` and `verdict: claim broken` — the :20 and
:40 slots slip to 25 and 50 because their bus has not returned; every
other 15-minute gap inherits the slip, and the pattern 10/15 repeats
for as long as the two-bus fleet runs.

**Method — scheduling, communication, assumptions.** Walk the class
through these moves:

1. Ledger, not timetable: for each slot in order, `departure =
   max(slot, earliest return of any bus)`; the chosen bus returns at
   `departure + 25`. One row per slot, two state columns (each bus's
   back-at-depot time).
2. Slot :00 → bus 1 departs 0, back 25. Slot :10 → bus 2 departs 10,
   back 35. Slot :20 → bus 1 is back at 25, so departure 25 — the
   first broken promise.
3. Gaps inherit slips: 0→10 (10), 10→25 (15), 25→35 (10), 35→50
   (15), 50→60 (10). The claim "every ten minutes" is false exactly
   on the odd slots, forever — the pattern is periodic.
4. The fix is fleet arithmetic, not speed: headway 10 with a 25-minute
   loop needs ⌈25/10⌉ = 3 buses. The honest notice states the real
   range ("every 10–15 minutes") without spin.

**Where this class gets stuck.** Students compute when the *bus* is
late and forget the *slot* also moved (departure is max of both), or
they let a bus serve a slot while still looping. The second stall is
treating the claim as "roughly true" — pin the exact gaps and the
periodicity before writing the notice.

## Five-minute teaching sequence

Minute 0–1 — **Read and analyse.** Expect the two-state insight ("where
are the two buses?"). Watch for: averaging the loop or ignoring it.
Minute 1–3 — **Develop an approach.** Expect the ledger through :30 at
least; a correct ledger with a gap slip is partial credit. Watch for:
bus 1 serving slot :20 at minute 20 (it is still looping).
Minute 3–5 — **Compare and write.** Expect the gap list and the notice
drafted; pairs compare which slots broke.
Reveal and discuss — keep the reveal inside 10 minutes so the exit question still fits.

## Difficulty adaptation

- **Simplify.** One bus, three slots — the ledger degenerates to
  departures 0, 25, 50.
- **Extend.** Three buses: the claim holds at the depot (25/10 ≤ 3);
  ask what breaks first — depot gaps or stop-level crowding.
- **Hints (progressive).**
  1. *Re-orient:* "Write the return time of the :00 bus before any
     other slot."
  2. *Structure:* "One row per slot: scheduled, actual, which bus,
     back-at-depot."
  3. *Near-answer:* the common wrong turn is letting a looping bus
     take a slot — undo that choice and re-derive the step it breaks.

## Reference solution (pseudocode)

```
free[1..fleet] <- 0
FOR EACH slot IN scheduled_slots:
    b <- bus with smallest free[b]
    dep <- max(slot, free[b])
    OUTPUT dep
    free[b] <- dep + loop
gaps <- differences of consecutive departures
verdict <- "holds" IF all gaps <= headway ELSE "broken"
```

## Reference solution (Python)

```python
LEGS = [4, 6, 7, 8]
LOOP = sum(LEGS)                     # 25 minutes
SLOTS = list(range(0, 60, 10))       # :00 .. :50
FLEET = 2

def ledger(slots, fleet, loop):
    free = [0] * fleet
    deps = []
    for s in slots:
        b = min(range(fleet), key=lambda i: free[i])
        dep = max(s, free[b])
        deps.append(dep)
        free[b] = dep + loop
    return deps

if __name__ == "__main__":
    deps = ledger(SLOTS, FLEET, LOOP)
    gaps = [b - a for a, b in zip(deps, deps[1:])]
    print("departures", deps, "gaps", gaps)
    print("verdict:", "claim holds" if all(g <= 10 for g in gaps)
          else "claim broken")
```

The code is runnable as-is; executing the file prints the worked instance
so you can demo it live on the projector.

## Edge cases

- A slot earlier than any return (gridlocked fleet) — `max` delays the
  departure; gaps grow until a bus returns.
- Loop time exactly equal to headway × fleet — the boundary where the
  claim just holds; test one minute more.
- A zero-length leg — loop shrinks, ledger still valid.

## Alternative approaches

- Simulation with a minute-tick clock — same answers, far more work;
  event-driven ledger is the teaching point.
- Average-gap reporting ("mean gap ≈ 12 min") — hides the broken
  promise; exactly the summary the poster's writers would like.
- Adding a buffer to the loop time (25 → 28 for "real traffic") —
  changes the fleet needed to 3 either way; good extension discussion.
- **Cost.** Linear in slots with a constant fleet scan; the insight is
  that a timetable claim is checkable in O(slots) arithmetic.

## Common pitfalls

- Letting a busy bus serve a slot (no state variable).
- Forgetting that a late departure also delays the *next* return.
- Reporting the average gap instead of the actual gaps.
- Writing a notice that promises what the ledger contradicts.

## Reveal script

1. Display the case and start the timer (5 minutes). While students work,
   circulate and read shoulders; pick one conventional attempt and one
   surprising one for the board.
2. Ask first: "Where are the two buses at minute 20?"
3. Walk the ledger slot by slot on the board, the room calling
   departures and returns.
4. Surface the wrong turn directly: the phantom free bus — ask what the
   state column says for bus 1 at :20.
5. Show the reference Python, run it on the worked instance, and let the
   class compare with their own answers.
6. Close by naming the technique — "fleet ledger under a cadence
   promise" — and hand over the discussion prompt about the
   three-minute shortcut.

## Assessment use

- **Formative use.** discussion-grade: mark ledger discipline and the
  honesty of the notice over the raw verdict.
- **Mini-rubric (10 points).**
  - *Structure (2):* per-slot ledger with bus state before numbers.
  - *Method (3):* max(slot, return) rule applied in order; both buses
    tracked.
  - *Result (3):* departures 0/10/25/35/50/60, gaps 10/15/10/15/10,
    correct verdict.
  - *Communication (2):* notice states the real range without spin.
- **Follow-up check.** The loop gains one minute (26): which slots
  slip now, and does the fleet answer change?
