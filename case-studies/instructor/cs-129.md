## Reasoning walkthrough

**Worked instance.** The six-row marks table and the office's written
policy: blank or `abs` means absent; `999` is a recheck sentinel, not a
mark.

**Expected result.** demo prints `included 3, absent 2, recheck 1,
mean 72.3` — Ayla 72, Deniz 64, Ferid 81 are included (mean 217/3 =
72.333… → 72.3); Ben (blank) and Cemre (`abs`) are absent; Elif (999)
is recheck.

**Method — validation, missing values, communication.** Walk the class
through these moves:

1. Read the *policy* before the data: the rules define three classes,
   so the program's first job is classification, not arithmetic.
2. Classify row by row, naming the rule invoked each time — the
   trace *is* the answer's audit trail.
3. Compute the mean only over rows classified `include`, and keep the
   counts visible: a mean with no denominator story is unauditable.
4. End with the failure mode: a program that reduces everything to
   "numeric or not" would average 999 in (mean becomes 304.0, silently
   wrong) — the sentinel must be intercepted by policy, not by chance.

**Where this class gets stuck.** Students commonly bucket all missingness
together ("not a real mark") and lose the absent/recheck distinction the
policy exists to make. The second stall is computing the mean first and
classifying later — force the order: classify, count, then average.

## Five-minute teaching sequence

Minute 0–1 — **Read and analyse.** Expect the three classes named and
at least one row placed in each. Watch for: reading the data before the
policy (the policy is the spec).
Minute 1–3 — **Develop an approach.** Expect a classification of all six
rows; a correct classification with a mean slip is partial credit.
Watch for: 999 silently included in the mean.
Minute 3–5 — **Compare and write.** Expect the three-part deliverable
sketched (classes, counts, mean) and the "what breaks" sentence drafted.
If most pairs stall, give the structure hint whole-class rather than
pair by pair.
Reveal and discuss — keep the reveal inside 10 minutes so the exit question still fits.

## Difficulty adaptation

- **Simplify.** Give the three classes as row labels and ask only for
  the counts; then remove one label and let them re-derive it.
- **Extend.** Add a row `Gül,abs ` (trailing space) and a row with a
  comma inside the mark field; ask what the *file format* discussion is.
- **Hints (progressive).**
  1. *Re-orient:* "How many distinct reasons can a mark be missing for?"
  2. *Structure:* "One pass: classify each row with the rule name, then
     aggregate only the includes."
  3. *Near-answer:* the common wrong turn is treating 999 as numeric —
     undo that choice and re-derive the step it breaks.

## Reference solution (pseudocode)

```
classes <- {include: [], absent: [], recheck: []}
FOR EACH row IN marks
    IF mark IS blank OR mark == "abs"  THEN classes.absent APPEND row
    ELSE IF mark == 999                THEN classes.recheck APPEND row
    ELSE                                    classes.include APPEND row
OUTPUT count per class, mean of classes.include (1 decimal)
```

## Reference solution (Python)

```python
RAW = [("Ayla", "72"), ("Ben", ""), ("Cemre", "abs"),
       ("Deniz", "64"), ("Elif", "999"), ("Ferid", "81")]

def classify(raw):
    classes = {"include": [], "absent": [], "recheck": []}
    for name, mark in raw:
        m = mark.strip()
        if m == "" or m == "abs":
            classes["absent"].append(name)
        elif m == "999":
            classes["recheck"].append(name)
        else:
            classes["include"].append((name, float(m)))
    return classes

if __name__ == "__main__":
    c = classify(RAW)
    mean = sum(v for _, v in c["include"]) / len(c["include"])
    print(f"included {len(c['include'])}, absent {len(c['absent'])}, "
          f"recheck {len(c['recheck'])}, mean {mean:.1f}")
```

The code is runnable as-is; executing the file prints the worked instance
so you can demo it live on the projector.

## Edge cases

- A mark that is whitespace only (`" "`) — blank after stripping.
- A mark equal to `"999"` typed as `0999` — the sentinel must match the
  policy's exact token; this file format cannot express both.
- The include list empty (everyone absent) — the mean is undefined and
  must not print a number.

## Alternative approaches

- Regular-expression routing of every row in one step — compact, but the
  rule names become harder to audit than an explicit branch chain.
- A dict of predicates mapped to classes: scales when the policy grows,
  overkill at six rows; mention as the lecture-13 preview.
- Dropping the recheck class entirely and reporting two counts — fails
  the office's actual workflow (they must phone invigilators).
- **Cost.** One pass over n rows, constant work per row; any variant is
  linear — the difference is auditability, not speed.

## Common pitfalls

- Averaging first, classifying later — the mean inherits the sentinel.
- Collapsing absent and recheck into one "missing" bucket.
- Comparing the raw field without stripping whitespace.
- Reporting the mean without stating which rows entered it.

## Reveal script

1. Display the case and start the timer (5 minutes). While students work,
   circulate and read shoulders; pick one conventional attempt and one
   surprising one for the board.
2. Ask first: "How many *kinds* of missing is this file showing?"
3. Walk the classification row by row on the board, calling the rule
   name for each row before revealing the class.
4. Surface the wrong turn directly: averaging 999 in — ask the room what
   number a naive program prints (304.0) and who would notice.
5. Show the reference Python, run it on the worked instance, and let the
   class compare with their own answers.
6. Close by naming the technique — "validation before aggregation" — and
   hand over the discussion prompt about the `72,0` row.

## Assessment use

- **Formative use.** discussion-grade: mark classification quality and
  rule naming rather than the final mean.
- **Mini-rubric (10 points).**
  - *Structure (2):* three classes named before any computation.
  - *Method (3):* each row classified under the stated rule; counts kept
    visible.
  - *Result (3):* included 3 / absent 2 / recheck 1 / mean 72.3, and the
    naive-program failure named.
  - *Communication (2):* assumptions stated; the mean's denominator
    reported with it.
- **Follow-up check.** The office adds "ECE" as an excused-code: which
  branch changes, and does the mean move?
