## Reasoning walkthrough

**Worked instance.** next(i) cycles: 1->2->3->4->2 (cycle of length 3); slow/fast pointers from 1

**Expected result.** demo prints True for the cyclic list and 'open chain: need a stop rule' for the acyclic one — they meet because the gap closes by exactly 1 each step

**Method — invariants and two pointers.** Walk the class through these moves:

1. Define the pointers and the region each is responsible for.
2. State the invariant in one sentence: what is always true?
3. Derive the movement rule from the invariant — never memorise it.
4. Argue termination: what strictly shrinks every iteration?

**Where this class gets stuck.** The gap between fast (2 steps) and slow (1 step) shrinks by exactly 1 per round - so it must reach 0. Expect the first
five minutes to produce moving both pointers on a branch that should move one as the
most common wrong turn; plan the reveal around it.


## Five-minute teaching sequence

Minute 0–1 — **Read and analyse.** Expect inputs, outputs, and at least

rule. Watch for: retelling the story without extracting the decision.
Minute 1–3 — **Develop an approach.** Expect a rule or a first-step

Minute 3–5 — **Compare and write.** Expect the update rule or loop
skeleton written down, pairs comparing orders of operations. If most

## Reference solution (pseudocode)

    slow <- start
    WHILE true DO
        slow <- next_fn(slow)
        fast <- next_fn(next_fn(fast))

            RETURN true

## Reference solution (Python)

```python
def has_cycle(next_fn, start):
    slow = fast = start
    while True:
        slow = next_fn(slow)
        fast = next_fn(next_fn(fast))
        if slow == fast:
            return True

if __name__ == "__main__":
    nxt = {1: 2, 2: 3, 3: 4, 4: 2}
    print(has_cycle(lambda i: nxt[i], 1))   # True
    nxt_open = {1: 2, 2: 3, 3: None}
    print(has_cycle(lambda i: nxt_open.get(i), 1) if False else "open chain: need a stop rule")
```

## Edge cases

- Termination: name the update that guarantees the loop ends, and check it on the smallest input.
- Empty or single-item input: decide what is returned and what must NOT be printed.
- Degenerate values: zero, negatives, and duplicates among the instance's data.


## Alternative approaches

- The gap between fast (2 steps) and slow (1 step) shrinks by exactly 1 per round - so it must reach 0.
- Rewrite the while-loop as a bounded for-loop over the data (or vice versa) and compare which version makes termination obvious.
- A table filled by hand before any code: for the size of instance here it is both a solution and the test oracle.


## Common pitfalls

- Moving both pointers on a branch that should move one.
- An update path that never moves the state — the loop that never ends; test on an interval of size two.
- Reporting the answer without the rule that produced it — the decision becomes uncheckable.

1. Display the case and start the timer (5 minutes). While students work,

2. Ask first: 'What must stay true about the two regions after every single move?'
3. Walk the worked instance (next(i) cycles: 1->2->3->4->2 (cycle of length 3); slow/fast pointers from 1) on the board

4. Surface the wrong turn directly: 'moving both pointers on a branch that should move one' — ask the room

5. Show the reference Python, run it on the worked instance, and let the
   class compare with their own answers.
6. Close by naming the technique — "invariants and two pointers" — and hand over the
   discussion prompt: **"Restate the invariant in your own words — is yours strong enough to prove the answer?"**


## Assessment use

- **Formative use.** discussion-grade: mark assumption quality and rule precision rather than the final number, and expect the full cycle to run long.
- **Mini-rubric (10 points).**
  - *Structure (2):* inputs, outputs, and the binding constraint named before any computation.
  - *Method (3):* the stated moves executed — especially "State the invariant in one sentence: what is always true?"
    and "Derive the movement rule from the invariant — never memorise it".
  - *Result (3):* the worked instance computed correctly (they meet inside the cycle; meeting guaranteed because the gap…),
    and the answer survives the smallest and the boundary input.
  - *Communication (2):* assumptions stated; the answer reports which rule produced it.
- **Follow-up check.** Which update line guarantees termination? Delete it mentally: what goes wrong first?
