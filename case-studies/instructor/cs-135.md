## Reasoning walkthrough

**Worked instance.** Eight students' study hours with pass/fail labels;
one rule; two standardisation orders — statistics from all rows (leaky)
vs from the training rows only (correct).

**Expected result.** demo prints `leaky: scaled -0.0945 → fail |
correct: scaled +0.4082 → pass` — student "7" flips from fail to pass
once the test rows stop helping compute the yardstick; that is
leakage shown as a **decision flip**, not an abstract warning.

**Method — leakage, evaluation, communication.** Walk the class
through these moves:

1. Inventory the flow of information: the leaky pipeline computes mean
   and sd from all eight rows *before* the split, so each held-out row
   influences the threshold it is judged by. Name it in one sentence a
   dean understands: "the exam graded itself with an answer key it
   helped write".
2. Correct order: split → compute statistics on training rows only →
   transform train and test with those training statistics → apply the
   rule.
3. Work the flip by hand: leaky mean 7.375, population sd ≈ 3.9930;
   scaled 7 → −0.0945 → predict fail. Correct: training rows are
   4, 4, 6, 10 → mean 6, population sd 2.8284; scaled 7 → +0.4082 →
   predict pass. One student, two verdicts.
4. The second leak: the team's "test accuracy on 20 held-out rows"
   was computed on a split chosen *after* everyone had seen all 40
   rows — a random split reported as unbiased needs a protocol fixed
   in advance, not one picked post hoc.

**Where this class gets stuck.** Students accept scaling as harmless
preprocessing — the flip is chosen to be undeniable. The second stall
is "the number is only slightly optimistic": push on the flip (a
student's fate changed) and on the second leak; the damage is not the
optimism, it is the unearned confidence.

## Five-minute teaching sequence

Minute 0–1 — **Read and analyse.** Expect the information-flow question
named ("who computes the mean, from whom?"). Watch for: treating
scaling as cosmetic.
Minute 1–3 — **Develop an approach.** Expect the pipeline order fixed
and the flip computed; a correct flip with a rounding slip is partial
credit. Watch for: sample sd (n−1) — this dataset states population
sd; either convention is fine if named and used consistently.
Minute 3–5 — **Compare and write.** Expect the dean sentence drafted
and the second leak hunted.
Reveal and discuss — keep the reveal inside 12 minutes; the prose
deliverable needs the extra time.

## Difficulty adaptation

- **Simplify.** Provide both (mean, sd) pairs and ask only for the two
  scaled values and the flip.
- **Extend.** Ask which test rows *cannot* flip: a row scales to the
  same sign under both pipelines exactly when both means sit on the
  same side of it — have them verify 12 and 14 never flip here.
- **Hints (progressive).**
  1. *Re-orient:* "Who computes the mean, and from whom?"
  2. *Structure:* "Split → training stats → transform both sides."
  3. *Near-answer:* the common wrong turn is mixing sd conventions —
     undo that choice and re-derive the step it breaks.

## Reference solution (pseudocode)

```
split rows into train, test
mu, sd <- computed over TRAIN ONLY          // the fix
for each row: scaled <- (hours - mu) / sd
predict pass IF scaled >= 0
// leaky variant: mu, sd computed over ALL rows before the split.
```

## Reference solution (Python)

```python
ROWS = [2, 4, 4, 6, 7, 10, 12, 14]
TEST = {2, 7, 12, 14}

def stats(xs):
    m = sum(xs) / len(xs)
    var = sum((x - m) ** 2 for x in xs) / len(xs)
    return m, var ** 0.5

def predict(hour, mu, sd):
    return "pass" if (hour - mu) / sd >= 0 else "fail"

if __name__ == "__main__":
    mu_l, sd_l = stats(ROWS)                       # leaky: all rows
    train = [x for x in ROWS if x not in TEST]
    mu_c, sd_c = stats(train)                      # correct: train only
    x = 7
    print("leaky:", round((x - mu_l) / sd_l, 4), "->", predict(x, mu_l, sd_l),
          "| correct:", round((x - mu_c) / sd_c, 4), "->",
          predict(x, mu_c, sd_c))
```

The code is runnable as-is; executing the file prints the worked instance
so you can demo it live on the projector.

## Edge cases

- The test row's value equals the training mean exactly — scaled 0
  under the correct pipeline; the rule's `>= 0` boundary decides.
- A training set with zero variance — sd 0 breaks the transform; the
  pipeline must define behaviour before scaling.
- Rounding mid-computation — four decimals at the end only, or the
  flip can disappear arithmetically.

## Alternative approaches

- Report accuracy with the leak and a warning label — rejected: the
  flip shows the label does not survive contact with a stakeholder.
- Cross-validation — the grown-up fix; at n = 8 it degenerates, but
  name it as what "compute stats inside each fold" becomes at scale.
- Rank-based rule (pass if above the training median) — different
  rule; the median is still a statistic someone must compute *after*
  the split.
- **Cost.** All variants are O(n); the expensive thing is a wrong
  decision, which is why pipeline order is audited before accuracy is
  quoted.

## Common pitfalls

- Sample vs population sd mixed between the two pipelines.
- Computing statistics "on all rows" twice without noticing.
- Believing accuracy as a number without asking who shaped it.
- The dean reply arguing rhetoric instead of citing pipeline order.

## Reveal script

1. Display the case and start the timer (5 minutes). While students work,
   circulate and read shoulders; pick one conventional attempt and one
   surprising one for the board.
2. Ask first: "Who computes the mean, and from whom?"
3. Build the pipeline order on the board: split → train-stats →
   transform → rule; then the leaky variant beside it.
4. Surface the wrong turn directly: harmless-preprocessing — compute
   both scalings of 7 live and watch the verdict flip.
5. Show the reference Python, run it on the worked instance, and let the
   class compare with their own answers.
6. Close by naming the technique — "statistics belong to the training
   split" — and hand over the discussion prompt about immateriality.

## Assessment use

- **Formative use.** discussion-grade: mark the flip argument and the
  pipeline-order fix over raw accuracy talk.
- **Mini-rubric (10 points).**
  - *Structure (2):* information flow described before numbers.
  - *Method (3):* both scalings computed with one stated sd convention.
  - *Result (3):* leaky −0.0945 → fail vs correct +0.4082 → pass;
    second leak named.
  - *Communication (2):* dean sentences non-technical and accurate.
- **Follow-up check.** Move the rule's threshold to 0.5: does the flip
  survive, and what does that tell you about thresholds chosen after
  seeing test data?
