## Reasoning walkthrough

**Worked instance.** n people, 365 equally likely birthdays (ignore leap days)

**Expected result.** P(no shared) = 365/365 x 364/365 x ... ; n=23 gives P(shared) ~ 50.7%

**Method — counting and probability.** Walk the class through these moves:

1. Frame the question: how many outcomes, and how many favourable?
2. Decide ordered vs unordered, with vs without replacement — in words first.
3. Compute with the multiplication/addition principles (or complements).
4. Check the count by brute-force enumeration when small.

**Where this class gets stuck.** No shared birthday: multiply falling terms (365-i)/365. Find the first n where 1 - product exceeds 0.5. Expect the first
five minutes to produce adding situations that multiply (wearing a shirt and trousers) as the
most common wrong turn; plan the reveal around it.

## Reference solution (pseudocode)

FUNCTION shared_probability(n, days)
    p_unique <- 1.0
    FOR EACH i IN range 0..n DO
        p_unique <- p_unique * (days - i) / days
    RETURN 1.0 - p_unique
FUNCTION first_over(threshold)
    n <- 1
    WHILE shared_probability(n) < threshold DO
        n <- n + 1
    RETURN n
// demo run: OUTPUT shared_probability(23)

## Reference solution (Python)

```python
def shared_probability(n, days=365):
    p_unique = 1.0
    for i in range(n):
        p_unique *= (days - i) / days
    return 1.0 - p_unique

def first_over(threshold=0.5):
    n = 1
    while shared_probability(n) < threshold:
        n += 1
    return n

if __name__ == "__main__":
    print(shared_probability(23))   # ~0.507
    print(first_over())             # 23
```

## Edge cases

- Termination: name the update that guarantees the loop ends, and check it on the smallest input.
- Empty or single-item input: decide what is returned and what must NOT be printed.
- Degenerate values: zero, negatives, and duplicates among the instance's data.
- Rounding: say where values are rounded and why a last digit may differ between two correct attempts.


## Alternative approaches

- No shared birthday: multiply falling terms (365-i)/365. Find the first n where 1 - product exceeds 0.5.
- Rewrite the while-loop as a bounded for-loop over the data (or vice versa) and compare which version makes termination obvious.
- An explicit stack or a plain loop instead of the recursion: identical visits, no call-stack growth.
- **Cost.** Linear: one visit per item, a constant amount of work per visit; the alternatives shift exactly this cost.


## Common pitfalls

- Adding situations that multiply (wearing a shirt and trousers).
- An update path that never moves the state — the loop that never ends; test on an interval of size two.
- Comparing floating-point values for exact equality instead of a tolerance (or rounding at the very end, not mid-computation).
- Reporting the answer without the rule that produced it — the decision becomes uncheckable.
