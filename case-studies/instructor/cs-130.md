## Reasoning walkthrough

**Worked instance.** Two exports of the same class: A with `S-`-prefixed
ids, B with bare ids, timestamps, and one re-registration plus one new
student.

**Expected result.** demo prints `unique 6 | removed A-side dups
['0007', '0042', '0117', '0203'] | flagged: 0117 name-mismatch; 0450
no-A-record | escalate: no-shared-id pairs` — six distinct people
survive; the four A-rows whose ids reappear in B are removed in
favour of B's timestamped rows; Petra's name differs across systems
and Tara exists only in B, so both are merged-by-key but flagged; the
escalate item is the rule for matching without ids.

**Method — deduplication, matching, missing values.** Walk the class
through these moves:

1. Normalise the key first: strip the `S-` prefix (or, symmetrically,
   add it) so both systems speak one id language. Nothing else in the
   rule works until the keys are comparable.
2. Decide the winner *before* seeing conflicts: latest timestamp wins
   (B is the newer system; `t` is monotone; A rows carry no time and
   lose to any B twin). A rule invented per-row is not a rule.
3. Merge ≠ ignore: every id present in both exports keeps only its
   newest row — here the four A-side rows for 0007, 0042, 0117, 0203
   are removed as duplicates, which is exactly right, not alarming.
4. Flag what the rule cannot decide: a key present in only one export
   (0450) and a name mismatch under a shared key (0117) are both
   "merged but flagged". Escalate the genuinely undecidable: matching
   people with no shared id.

**Where this class gets stuck.** Students reach for name matching first
because names are human-readable — but "Petra K." vs "Petra" shows the
name is the *unreliable* field here. The second stall is deleting
singlesystem records as errors instead of flagging them: one export
being incomplete is the normal case, not an anomaly.

## Five-minute teaching sequence

Minute 0–1 — **Read and analyse.** Expect the key question named ("what
makes two rows the same student?"). Watch for: starting to dedupe
before choosing the key.
Minute 1–3 — **Develop an approach.** Expect a normalisation rule and a
conflict winner; a correct count with a silent drop of 0450 is partial
credit. Watch for: name-based merging ("Petra K." split into two people).
Minute 3–5 — **Compare and write.** Expect the flag list drafted and the
escalation sentence attempted; pairs compare which rows they flagged.
Reveal and discuss — keep the reveal inside 10 minutes so the exit question still fits.

## Difficulty adaptation

- **Simplify.** Remove the name variant and the re-registration; ask
  only for normalisation + count (answer: 6, one dup).
- **Extend.** Add an export C with the same ids but `S`/`s` case
  variants, and one row where the newest timestamp carries an *older*
  email — winner rule vs field-level merge.
- **Hints (progressive).**
  1. *Re-orient:* "Decide the key before the winner — not after."
  2. *Structure:* "Normalise keys, group by key, pick winner per group,
     flag the rest."
  3. *Near-answer:* the common wrong turn is trusting names over ids —
     undo that choice and re-derive the step it breaks.

## Reference solution (pseudocode)

```
FOR EACH row IN B: key <- strip_prefix(id, "S-")
groups <- group rows from A and B by key
FOR EACH key IN groups:
    winner <- row with max timestamp (A rows: t = 0)
    losers <- others
    IF winner appears in both exports with different names THEN flag key
    IF key in only one export THEN flag key
OUTPUT len(groups), removed losers, flags, escalation rule
```

## Reference solution (Python)

```python
A = {"S-0007": "Mia", "S-0042": "Omar", "S-0117": "Petra",
     "S-0203": "Quan", "S-0311": "Rosa"}
B = [("0007", "Mia", 1), ("0042", "Omar", 2), ("0042", "Omar", 5),
     ("0117", "Petra K.", 3), ("0203", "Quan", 4), ("0450", "Tara", 6)]

def dedupe(a, b):
    groups = {}
    for sid, name in a.items():            # normalise: strip S- prefix
        groups[sid.removeprefix("S-")] = [(0, name, "A")]
    for sid, name, t in b:
        groups.setdefault(sid, []).append((t, name, "B"))
    removed, flagged = [], []
    for sid, rows in sorted(groups.items()):
        rows.sort()                        # latest timestamp wins
        removed += [(sid, r) for r in rows[:-1]]
        names = {r[1] for r in rows}
        if len(names) > 1:
            flagged.append((sid, "name-mismatch"))
        if {src for _, _, src in rows} == {"B"}:
            flagged.append((sid, "no-A-record"))
    return len(groups), sorted({sid for sid, _ in removed}), flagged

if __name__ == "__main__":
    n, removed, flagged = dedupe(A, B)
    print(f"unique {n} | removed A-side dups", removed, "|",
          "flagged:", "; ".join(f"{s} {r}" for s, r in flagged),
          "| escalate: no-shared-id pairs")
```

The code is runnable as-is; executing the file prints the worked instance
so you can demo it live on the projector.

## Edge cases

- A key with more than two rows (triple registration) — the winner rule
  must survive iteration.
- Timestamps equal across systems — the tie rule must be named (A
  loses because it is the older system).
- An id in B that is only whitespace after prefix-stripping.

## Alternative approaches

- Field-level merge (newest email, newest name separately) — better data,
  harder to explain; worth naming against the whole-row winner.
- Fuzzy name matching as a fallback — out of scope here, and the
  escalation question is exactly about who owns that risk.
- Sorting both exports and scanning pairwise — same result, but the
  grouping formulation survives when exports arrive unsorted.
- **Cost.** Linear in rows plus a sort per group (tiny groups here);
  the scalable view is grouping by key, not comparing all pairs.

## Common pitfalls

- Merging on names instead of normalised ids.
- Silently dropping single-export rows instead of flagging them.
- Keeping the older row because it appeared "first".
- Declaring the job done at the count — the flags are the deliverable.

## Reveal script

1. Display the case and start the timer (5 minutes). While students work,
   circulate and read shoulders; pick one conventional attempt and one
   surprising one for the board.
2. Ask first: "What makes two rows the same student — and what makes
   them different people?"
3. Walk the normalisation → group → winner → flag chain on the board,
   class calling the next step.
4. Surface the wrong turn directly: name-based matching — ask what
   "Petra K." would have cost them.
5. Show the reference Python, run it on the worked instance, and let the
   class compare with their own answers.
6. Close by naming the technique — "key-first deduplication" — and hand
   over the discussion prompt about the id-less third export.

## Assessment use

- **Formative use.** discussion-grade: mark rule explicitness and flag
  completeness rather than the raw count.
- **Mini-rubric (10 points).**
  - *Structure (2):* normalisation rule stated before grouping.
  - *Method (3):* winner rule explicit; flags for one-export and
    name-mismatch rows.
  - *Result (3):* unique 6, all four A-side duplicates removed, flags
    correct, escalation named.
  - *Communication (2):* assumptions stated; flags carry reasons.
- **Follow-up check.** A B-row arrives with a timestamp *earlier* than
  its A twin: what does your rule do, and is that right?
