**Expected result.** demo prints '4.46 | 21.96' — mean waits at rho = 0.8 versus near capacity; waits are non-linear in load, collapsing as arrivals approach service rate

**Method — simulation and randomness.** Walk the class through these moves:

1. Tell the story of one trial precisely (what is random, what is fixed?).
2. Choose the randomness source and any seed for reproducibility.
3. Run many trials; record the statistic per trial.
4. Summarise the distribution; compare against exact reasoning where possible.

**Where this class gets stuck.** Simulate minute by minute: arrival with prob rate/60, service finishes with prob srv/60. Plot (or tabulate) the average wait. Expect the first

## Reference solution (pseudocode)

FUNCTION queue_sim(rate_ph, srv_ph, minutes, seed)
    r <- random.Random(seed)
    waiting <- 0
    total_wait <- 0
    served <- 0
    REPEAT minutes TIMES
        IF r.random() < rate_ph / 60 THEN
            waiting <- waiting + 1
        IF (waiting) AND (r.random() < srv_ph / 60) THEN
            total_wait <- total_wait + waiting
            served <- served + 1
            waiting <- waiting - 1
    RETURN total_wait / MAX(served, 1)
// demo run: OUTPUT ROUND(queue_sim(), 2)
// demo run: OUTPUT ROUND(queue_sim(5.9, 6.0), 2)


## Reference solution (Python)

```python
def queue_sim(rate_ph=4.0, srv_ph=5.0, minutes=50_000, seed=7):
    import random
    r = random.Random(seed)
    waiting = 0
    total_wait = 0
    served = 0
    for _ in range(minutes):
        if r.random() < rate_ph / 60:
            waiting += 1
        if waiting and r.random() < srv_ph / 60:
            total_wait += waiting
            served += 1
            waiting -= 1
    return total_wait / max(served, 1)

if __name__ == "__main__":
    print(round(queue_sim(), 2))          # modest queue at rho=0.8
    print(round(queue_sim(5.9, 6.0), 2))  # much worse near saturation
```

## Edge cases

- Empty or single-item input: decide what is returned and what must NOT be printed.
- Degenerate values: zero, negatives, and duplicates among the instance's data.
- Rounding: say where values are rounded and why a last digit may differ between two correct attempts.


## Alternative approaches

- Simulate minute by minute: arrival with prob rate/60, service finishes with prob srv/60. Plot (or tabulate) the average wait.
- Loop-first formulation versus a comprehension/direct-expression formulation — same result, different emphasis on state versus intent.
- A table filled by hand before any code: for the size of instance here it is both a solution and the test oracle.
- **Cost.** Linear: one visit per item, a constant amount of work per visit; the alternatives shift exactly this cost.


## Common pitfalls

- Unseeded randomness: results not reproducible.
- Comparing floating-point values for exact equality instead of a tolerance (or rounding at the very end, not mid-computation).
- Reporting the answer without the rule that produced it — the decision becomes uncheckable.

   next state at each step.
4. Surface the wrong turn directly: 'unseeded randomness: results not reproducible' — ask the room
   which quiet assumption it makes.
5. Show the reference Python, run it on the worked instance, and let the
   class compare with their own answers.
6. Close by naming the technique — "simulation and randomness" — and hand over the
   discussion prompt: **"What hidden assumption did the generator make, and when would it fail?"**

- **Mini-rubric (10 points).**

- **Follow-up check.** Where does rounding happen, and which digit may differ between two correct implementations?
