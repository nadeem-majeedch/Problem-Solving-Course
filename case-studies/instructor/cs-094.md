## Reasoning walkthrough

**Worked instance.** grid campus: S at (0,0), T at (2,2); corridors right/down/up; wall at (1,1)

**Expected result.** shortest walk 4 steps or 'unreachable' - BFS levels are distances

**Method — graphs and traversal.** Walk the class through these moves:

1. Model first: what are the nodes, what are the edges?
2. Choose the representation (adjacency list for sparse graphs).
3. Traverse with the right discipline: BFS for fewest steps, DFS for structure.
4. Keep a visited set — the difference between an algorithm and an infinite loop.

**Where this class gets stuck.** BFS from S; the first time you pop T, its level is the distance. Walls are just missing edges. Expect the first
five minutes to produce forgetting the visited set on graphs with cycles as the
most common wrong turn; plan the reveal around it.

## Reference solution (pseudocode)

FUNCTION shortest_walk(grid, start, goal)
    (rows, cols) <- (LENGTH(grid), LENGTH(grid[0]))
    q <- deque([(start, 0)])
    seen <- set{start}
    WHILE q DO
        ((r, c), d) <- q.popleft()
        IF (r, c) = goal THEN
            RETURN d
        FOR EACH (dr, dc) IN ((1, 0), (-1, 0), (0, 1), (0, -1)) DO
            (nr, nc) <- (r + dr, c + dc)
            IF (0 <= nr < rows) AND (0 <= nc < cols) AND (grid[nr][nc] != '#') AND ((nr, nc) not in seen) THEN
                add (nr, nc) to seen
                append ((nr, nc), d + 1) to q
    RETURN -1

## Reference solution (Python)

```python
from collections import deque

def shortest_walk(grid, start, goal):
    rows, cols = len(grid), len(grid[0])
    q = deque([(start, 0)])
    seen = {start}
    while q:
        (r, c), d = q.popleft()
        if (r, c) == goal:
            return d
        for dr, dc in ((1, 0), (-1, 0), (0, 1), (0, -1)):
            nr, nc = r + dr, c + dc
            if (0 <= nr < rows and 0 <= nc < cols and grid[nr][nc] != "#"
                    and (nr, nc) not in seen):
                seen.add((nr, nc))
                q.append(((nr, nc), d + 1))
    return -1

    g = [["S", ".", "."], [".", "#", "."], [".", ".", "T"]]
    print(shortest_walk(g, (0, 0), (2, 2)))   # 4
```

## Edge cases

- Termination: name the update that guarantees the loop ends, and check it on the smallest input.
- Empty or single-item input: decide what is returned and what must NOT be printed.
- Boundary positions: the first item, the last item, and the position one past each end (the i-1 / i+1 arithmetic).


## Alternative approaches

- BFS from S; the first time you pop T, its level is the distance. Walls are just missing edges.
- Rewrite the while-loop as a bounded for-loop over the data (or vice versa) and compare which version makes termination obvious.
- A table filled by hand before any code: for the size of instance here it is both a solution and the test oracle.
- **Cost.** Linear: one visit per item, a constant amount of work per visit; the alternatives shift exactly this cost.


## Common pitfalls

- Forgetting the visited set on graphs with cycles.
- An update path that never moves the state — the loop that never ends; test on an interval of size two.
- Mutating the caller's list when the result was meant to be a fresh one — the demo where the input 'changes by itself'.
- Off-by-one at the boundary: the update that is correct for the middle of the data and wrong at the two ends.
- Reporting the answer without the rule that produced it — the decision becomes uncheckable.
