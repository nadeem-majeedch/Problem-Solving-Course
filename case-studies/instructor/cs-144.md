## Reasoning walkthrough

**Worked instance.** Two staff notes that disagree about who receives
the `technical` versus `foundation` sheet; a draft flowchart that
never sends `foundation`.

**Expected result.** demo prints the four input classes with the
correct sheet per the reconciled rule — `empty -> general |
language -> technical | beginner-tools -> foundation | mixed
language+tools -> technical (language wins)` — plus the conflict
statement and the question that resolves it.

**Method — communication, requirements, assumptions.** Walk the class
through these moves:

1. Locate the disagreement precisely: Staff A routes *any* language
   mention to technical; Staff B wants *only-beginner-tools*
   applicants to get foundation. These collide on one class: an
   application listing a language **and** a spreadsheet (the mixed
   class). That identification is the deliverable, not a compromise.
2. Ask the question that flips the flowchart: "when an applicant
   lists both a language and beginner tools, which sheet?" — each
   answer changes exactly one arrow.
3. Complete the class list *before* drawing: empty, language-only,
   tools-only, mixed. The draft forgot `foundation` entirely and the
   mixed class; enumerating classes is the flowchart's real input.
4. Draw with one decision per diamond: "empty?" → "language?" →
   default foundation path; the default arrow is where unlisted
   classes land — the fourth deliverable names it.

**Where this class gets stuck.** Students reconcile by feeling ("send
both sheets?") instead of locating the disagreeing input class —
force the one-sentence conflict statement first. Second stall:
diamonds that ask two questions at once ("empty or toolless?"),
which cannot be drawn as a single decision.

## Five-minute teaching sequence

Minute 0–1 — **Read and analyse.** Expect the two rules restated as
predicates. Watch for: drafting the flowchart immediately.
Minute 1–3 — **Develop an approach.** Expect the mixed class found;
a correct flowchart without the conflict sentence is partial credit.
Watch for: a flowchart that sends nothing for the mixed class.
Minute 3–5 — **Compare and write.** Expect the clarifying question
and the extra input class named; pairs compare class lists.
Reveal and discuss — keep the reveal inside 10 minutes so the exit question still fits.

## Difficulty adaptation

- **Simplify.** Give the four classes; students place arrows only.
- **Extend.** Add the `portfolio` sheet for project links: which box
  changes, and does any earlier arrow reverse (no — the language
  check stays, a new parallel branch appears)?
- **Hints (progressive).**
  1. *Re-orient:* "Enumerate the input classes first; the flowchart
     is easy once the classes are complete."
  2. *Structure:* "One question per diamond; every class ends at
     exactly one sheet."
  3. *Near-answer:* the common wrong turn is the missing mixed
     class — undo that choice and re-derive the arrow it breaks.

## Reference solution (pseudocode)

```
IF application IS empty          -> general
ELSE IF lists_language(app)      -> technical
ELSE IF lists_tools_only(app)    -> foundation
ELSE                             -> general   // default: mixed or unknown
// conflict: A wants mixed -> technical; B's note is silent on mixed.
```

## Reference solution (Python)

```python
LANGS = {"python", "java", "c++", "javascript"}
TOOLS = {"spreadsheets", "excel", "slides"}

def classify(app):
    items = set(app.lower().split(", ")) - {""}
    if not items:
        return "empty"
    if items & LANGS:
        return "language"
    if items <= TOOLS:
        return "beginner-tools"
    return "mixed"

if __name__ == "__main__":
    for app in ("", "python", "spreadsheets",
                "python, spreadsheets"):
        print(repr(app), "->", classify(app))
```

The code is runnable as-is; executing the file prints the worked instance
so you can demo it live on the projector.

## Edge cases

- An application listing a tool *misspelled* ("exel") — lands in
  mixed; the classifier's vocabulary is itself a requirements
  question.
- Capitalisation and extra spaces — normalise before classifying or
  the classes leak.
- An application listing two languages — still the language class;
  the predicates are set-based, not counts.

## Alternative approaches

- Send both sheets to the mixed class — avoids the conflict
  decision, doubles mail; worth discussing as the "no decision"
  option and its cost.
- Ask the applicant to self-select — moves the ambiguity to the
  person least able to resolve it; rejected with reasons.
- A lookup table of exact strings — brittle the moment a new tool
  appears; the set-membership predicates generalise.
- **Cost.** One pass over a short list; the scarce resource is the
  office's decision, which the clarifying question obtains.

## Common pitfalls

- Drawing diamonds before enumerating input classes.
- Diamonds that test two conditions at once.
- Leaving the mixed class unrouted (no arrow).
- Treating the conflict as resolved without stating it.

## Reveal script

1. Display the case and start the timer (5 minutes). While students work,
   circulate and read shoulders; pick one conventional attempt and one
   surprising one for the board.
2. Ask first: "Which application makes A and B disagree?"
3. Build the class list on the board, then the flowchart beneath it.
4. Surface the wrong turn directly: the unrouted mixed class — ask
   what happens to that applicant in the draft.
5. Show the reference Python, run it on the worked instance, and let the
   class compare with their own answers.
6. Close by naming the technique — "enumerate classes, then route" —
   and hand over the discussion prompt about the portfolio sheet.

## Assessment use

- **Formative use.** discussion-grade: mark conflict identification
  and class completeness over flowchart neatness.
- **Mini-rubric (10 points).**
  - *Structure (2):* input classes enumerated before drawing.
  - *Method (3):* conflict stated as one input class; one question
    per diamond; every class routed.
  - *Result (3):* correct sheet per class under the stated
    reconciliation; default arrow named.
  - *Communication (2):* question phrased so either answer changes
    the chart.
- **Follow-up check.** Staff B accepts "mixed → technical": which
  arrow changes, and does any class become unreachable?
