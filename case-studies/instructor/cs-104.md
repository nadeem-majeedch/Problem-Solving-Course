## Reference solution (pseudocode)

FUNCTION exact_streak(n, p, k)
    dp <- [0.0] * k
    dp[0] <- 1.0
    done <- 0.0
    REPEAT n TIMES
        ndp <- [0.0] * k
        FOR EACH s IN range 0..k DO
            IF dp[s] = 0.0 THEN
                CONTINUE
            IF s = k - 1 THEN
                done <- done + dp[s] * p
            ELSE
                ndp[s + 1] <- ndp[s + 1] + dp[s] * p
            ndp[0] <- ndp[0] + dp[s] * (1 - p)
        dp <- ndp
    RETURN done
FUNCTION sim_streak(n, p, k, trials)
    random.seed(42)
    hits <- 0
    REPEAT trials TIMES
        streak <- 0
        REPEAT n TIMES
            IF random.random() < p THEN
                streak <- streak + 1
                best <- MAX(best, streak)
            ELSE
                streak <- 0
        IF best >= k THEN
            hits <- hits + 1
    RETURN hits / trials

## Reference solution (Python)

```python
def exact_streak(n=20, p=0.55, k=5):
    # dp[s]: probability that no k-run has happened yet and the current
    # winning streak is exactly s (s = 0..k-1). Completing a k-run is
    # absorbing: that probability mass moves to `done` and stays there.
    dp = [0.0] * k
    dp[0] = 1.0
    done = 0.0
    for _ in range(n):
        ndp = [0.0] * k
        for s in range(k):
            if dp[s] == 0.0:
                continue
            if s == k - 1:
                done += dp[s] * p          # a win here completes the run
            else:
                ndp[s + 1] += dp[s] * p
            ndp[0] += dp[s] * (1 - p)      # any loss ends the current streak
        dp = ndp
    return done

def sim_streak(n=20, p=0.55, k=5, trials=100_000):
    import random
    random.seed(42)
    hits = 0
    for _ in range(trials):
        streak = best = 0
        for _ in range(n):
            if random.random() < p:
                streak += 1
                best = max(best, streak)
            else:
                streak = 0
        if best >= k:
            hits += 1
    return hits / trials

if __name__ == "__main__":
    print(round(exact_streak(), 4), round(sim_streak(), 4))
```

## Edge cases

- Empty or single-item input: decide what is returned and what must NOT be printed.
- Boundary positions: the first item, the last item, and the position one past each end (the i-1 / i+1 arithmetic).
- Rounding: say where values are rounded and why a last digit may differ between two correct attempts.


## Alternative approaches

- Exact: dp over games tracking current streak capped at 5. Simulation must MATCH it - disagreement means a bug.
- Loop-first formulation versus a comprehension/direct-expression formulation — same result, different emphasis on state versus intent.
- A table filled by hand before any code: for the size of instance here it is both a solution and the test oracle.
- **Cost.** Linear: the exact recursion visits each game position once (O(n) states), and Monte Carlo is linear in the trial count; the alternatives shift exactly this cost.


## Common pitfalls

- Adding situations that multiply (wearing a shirt and trousers).
- Comparing floating-point values for exact equality instead of a tolerance (or rounding at the very end, not mid-computation).
- Off-by-one at the boundary: the update that is correct for the middle of the data and wrong at the two ends.
- Reporting the answer without the rule that produced it — the decision becomes uncheckable.
