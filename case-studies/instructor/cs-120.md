## Reasoning walkthrough

**Worked instance.** 4x4 grid, friends pairs (r1,c1)-(r2,c2) must not sit adjacent (share an edge); 6 students, 2 friend pairs

**Expected result.** a valid seating or 'impossible' - backtracking with adjacency pruning; report the search count

**Method — brute force and search spaces.** Walk the class through these moves:

1. Describe the search space precisely (what is one candidate?).
2. Count the space before enumerating it.
3. Enumerate systematically to avoid duplicates and gaps.
4. Filter with the constraint; prune what cannot succeed.

**Where this class gets stuck.** Place students cell by cell; prune the moment a friendship is violated. Count nodes visited - pruning is measurable. Expect the first
five minutes to produce enumerating unordered items in every order (n! instead of c(n,k)) as the
most common wrong turn; plan the reveal around it.

## Reference solution (pseudocode)

FUNCTION seating(grid_n, students, friend_pairs)
    cells <- {(r, c) for each r in range 0..grid_n; each c in range 0..grid_n}
    pos <- map{}
    nodes <- 0
    FUNCTION adjacent(p, q)
        RETURN ABS(p[0] - q[0]) + ABS(p[1] - q[1]) = 1
    FUNCTION ok(cell, s)
        FOR EACH (a, b) IN friend_pairs DO
            IF (a = s) AND (b in pos) AND (adjacent(pos[b], cell)) THEN
                RETURN false
            IF (b = s) AND (a in pos) AND (adjacent(pos[a], cell)) THEN
                RETURN false
        RETURN true
    FUNCTION bt(i)
        // (beyond pseudocode: Nonlocal)
        IF i = LENGTH(students) THEN
            RETURN true
        nodes <- nodes + 1
        FOR EACH cell IN cells DO
            IF (cell not in pos) AND (ok(cell, students[i])) THEN
                pos[cell] <- students[i]
                IF bt(i + 1) THEN
                    RETURN true
                // delete pos[cell]
        RETURN false
    IF bt(0) THEN
        RETURN (MAP(pos), nodes)
    RETURN (null, nodes)

## Reference solution (Python)

```python
def seating(grid_n, students, friend_pairs):
    cells = [(r, c) for r in range(grid_n) for c in range(grid_n)]
    pos = {}
    nodes = 0

    def adjacent(p, q):
        return abs(p[0] - q[0]) + abs(p[1] - q[1]) == 1

    def ok(cell, s):
        for (a, b) in friend_pairs:
            if a == s and b in pos and adjacent(pos[b], cell):
                return False
            if b == s and a in pos and adjacent(pos[a], cell):
                return False
        return True

    def bt(i):
        nonlocal nodes
        if i == len(students):
            return True
        nodes += 1
        for cell in cells:
            if cell not in pos and ok(cell, students[i]):
                pos[cell] = students[i]
                if bt(i + 1):
                    return True
                del pos[cell]
        return False

    if bt(0):
        return dict(pos), nodes
    return None, nodes

if __name__ == "__main__":
    print(seating(2, ["a", "b", "c", "d"], [("a", "b")]))
```

## Edge cases

- First occurrence of a key not yet in the map — the default path must produce a defined answer.
- Empty or single-item input: decide what is returned and what must NOT be printed.
- Boundary positions: the first item, the last item, and the position one past each end (the i-1 / i+1 arithmetic).


## Alternative approaches

- Place students cell by cell; prune the moment a friendship is violated. Count nodes visited - pruning is measurable.
- Loop-first formulation versus a comprehension/direct-expression formulation — same result, different emphasis on state versus intent.
- A plain list of (key, value) pairs instead of a map: fine at this size, but every lookup becomes a scan.
- **Cost.** Exponential in the worst case — the search tree can visit every seating; pruning cuts whole branches (measure the node count to see it), and the alternatives shift exactly this cost.


## Common pitfalls

- Enumerating unordered items in every order (n! instead of c(n,k)).
- Reading a key before it exists (the first occurrence) instead of using the default path.
- Off-by-one at the boundary: the update that is correct for the middle of the data and wrong at the two ends.
- Reporting the answer without the rule that produced it — the decision becomes uncheckable.
