## Reasoning walkthrough

**Worked instance.** meetings [(0,3), (1,2), (3,5), (4,7), (7,9)]

**Expected result.** max non-overlapping = 4: (1,2), (3,5), (7,9) + one of (0,3)/(4,7) variant -> verify count 4

**Method — recursion and dynamic programming.** Walk the class through these moves:

1. Define the subproblem in words (what does f(k) mean?).
2. Find the base case(s) — the smallest inputs answered directly.
3. Write the transition: how f(k) uses smaller answers.
4. Draw the call tree; memoise if subproblems repeat.

**Where this class gets stuck.** Sort by END time; take a meeting whenever it starts at/after the last taken end. Justify by exchange argument. Expect the first
five minutes to produce a missing or wrong base case = infinite recursion as the
most common wrong turn; plan the reveal around it.


## Five-minute teaching sequence

Minute 0–1 — **Read and analyse.** Expect inputs, outputs, and at least
one stated assumption named; the deciding quantity here is the input
rule. Watch for: retelling the story without extracting the decision.
Minute 1–3 — **Develop an approach.** Expect a rule or a first-step
computation on the instance; a correct rule with an arithmetic slip is
partial credit. Watch for: forgetting the tie-break — two equal input values must still be ordered deterministically.
Minute 3–5 — **Compare and write.** Expect the update rule or loop
skeleton written down, pairs comparing orders of operations. If most
pairs stall, give the structure hint from the difficulty ladder
(below) whole-class rather than pair by pair.
Reveal and discuss — keep the reveal inside 10 minutes so the exit question still fits.

## Reference solution (pseudocode)

FUNCTION max_meetings(ms)
    chosen <- []
    last_end <- REAL('-inf')
    FOR EACH (s, e) IN SORTED(ms; key = (m) -> m[1]) DO
        IF s >= last_end THEN
            append (s, e) to chosen
            last_end <- e
    RETURN chosen
// demo run: OUTPUT max_meetings([(0, 3), (1, 2), (3, 5), (4, 7), (7, 9)])


## Reference solution (Python)

```python
def max_meetings(ms):
    chosen = []
    last_end = float("-inf")
    for s, e in sorted(ms, key=lambda m: m[1]):
        if s >= last_end:
            chosen.append((s, e))
            last_end = e
    return chosen

if __name__ == "__main__":
    print(max_meetings([(0, 3), (1, 2), (3, 5), (4, 7), (7, 9)]))
```

## Edge cases

- Ties: two equal values may swap order in the input; the stated rule must pin the output.
- Empty or single-item input: decide what is returned and what must NOT be printed.
- Degenerate values: zero, negatives, and duplicates among the instance's data.


## Alternative approaches

- Sort by END time; take a meeting whenever it starts at/after the last taken end. Justify by exchange argument.
- Iterative table versus recursive formulation: same recurrence, different order of filling it; the loop version cannot overflow any call stack.
- Sort first, then scan once, versus scanning with extra bookkeeping and no sort: the sort pays for itself only when later steps reuse the order.
- **Cost.** The sort dominates the cost: n log n in the input size, everything after it is one cheap pass; the alternatives shift exactly this cost.


## Common pitfalls

- A missing or wrong base case = infinite recursion.
- Mutating the caller's list when the result was meant to be a fresh one — the demo where the input 'changes by itself'.
- Reporting the answer without the rule that produced it — the decision becomes uncheckable.


## Reveal script

1. Display the case and start the timer (5 minutes). While students work,
   circulate and read shoulders; pick one conventional attempt and one
   surprising one for the board.
2. Ask first: 'What is the smallest instance you can already solve — and how does a bigger one shrink onto it?'
3. Walk the worked instance (meetings [(0,3), (1,2), (3,5), (4,7), (7,9)]) on the board
   under the stated rule before any code appears; the class calls the
   next state at each step.
4. Surface the wrong turn directly: 'a missing or wrong base case = infinite recursion' — ask the room
   which quiet assumption it makes.
5. Show the reference Python, run it on the worked instance, and let the
   class compare with their own answers.
6. Close by naming the technique — "recursion and dynamic programming" — and hand over the
   discussion prompt: **"State f(k)'s meaning in words; is your statement precise enough to code from?"**


## Assessment use

- **Formative use.** discussion-grade: mark assumption quality and rule precision rather than the final number, and expect the full cycle to run long.
- **Mini-rubric (10 points).**
  - *Structure (2):* inputs, outputs, and the binding constraint named before any computation.
  - *Method (3):* the stated moves executed — especially "Find the base case(s) — the smallest inputs answered directly"
    and "Write the transition: how f(k) uses smaller answers".
  - *Result (3):* the worked instance computed correctly (max non-overlapping = 4: (1,2), (3,5), (7,9) + one of…),
    and the answer survives the smallest and the boundary input.
  - *Communication (2):* assumptions stated; the answer reports which rule produced it.
- **Follow-up check.** Two equal values swap places in the input: does the output change? Justify with the stated rule.
