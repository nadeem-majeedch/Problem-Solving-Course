## Reasoning walkthrough

**Worked instance.** friends: ada-bo, bo-cy, cy-dee, dee-ada, bo-dee (5 edges among 4); ego network of ada

**Expected result.** ada's circle: everyone (size 4) - connected graph; in general: BFS from the person

**Method — graphs and traversal.** Walk the class through these moves:

1. Model first: what are the nodes, what are the edges?
2. Choose the representation (adjacency list for sparse graphs).
3. Traverse with the right discipline: BFS for fewest steps, DFS for structure.
4. Keep a visited set — the difference between an algorithm and an infinite loop.

**Where this class gets stuck.** Nodes = people, edges = friendship. 'Indirect friends' = reachable set = BFS. Expect the first
five minutes to produce forgetting the visited set on graphs with cycles as the
most common wrong turn; plan the reveal around it.

## Reference solution (pseudocode)

FUNCTION circle_size(adj, start)
    seen <- set{start}
    q <- deque([start])
    WHILE q DO
        v <- q.popleft()
        FOR EACH u IN adj.get(v, default []) DO
            IF u not in seen THEN
                add u to seen
                append u to q
    RETURN LENGTH(seen)

## Reference solution (Python)

```python
from collections import deque

def circle_size(adj, start):
    seen = {start}
    q = deque([start])
    while q:
        v = q.popleft()
        for u in adj.get(v, []):
            if u not in seen:
                seen.add(u)
                q.append(u)
    return len(seen)

if __name__ == "__main__":
    adj = {"ada": ["bo", "dee"], "bo": ["ada", "cy", "dee"],
           "cy": ["bo", "dee"], "dee": ["cy", "ada", "bo"]}
    print(circle_size(adj, "ada"))   # 4
```

- **Cost.** Linear: one visit per item, a constant amount of work per visit; the alternatives shift exactly this cost.


## Common pitfalls

- Forgetting the visited set on graphs with cycles.
- An update path that never moves the state — the loop that never ends; test on an interval of size two.
- Mutating the caller's list when the result was meant to be a fresh one — the demo where the input 'changes by itself'.
- Reporting the answer without the rule that produced it — the decision becomes uncheckable.
