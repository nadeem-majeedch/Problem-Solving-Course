## Reasoning walkthrough

**Worked instance.** starters {ada}; edges 1 hour each; graph of 6 friends

**Expected result.** time until everyone knows = max BFS level over all reachable; disconnected -> 'never' for some

**Method — graphs and traversal.** Walk the class through these moves:

1. Model first: what are the nodes, what are the edges?
2. Choose the representation (adjacency list for sparse graphs).
3. Traverse with the right discipline: BFS for fewest steps, DFS for structure.
4. Keep a visited set — the difference between an algorithm and an infinite loop.

**Where this class gets stuck.** Multi-source BFS: put ALL starters in the queue at distance 0; answer = max distance. Expect the first
five minutes to produce forgetting the visited set on graphs with cycles as the
most common wrong turn; plan the reveal around it.

## Reference solution (pseudocode)

FUNCTION rumour_time(adj, starters)
    dist <- map{s: 0 for s in starters}
    q <- deque(starters)
    WHILE q DO
        v <- q.popleft()
        FOR EACH u IN adj.get(v, default []) DO
            IF u not in dist THEN
                dist[u] <- dist[v] + 1
                append u to q
    everyone <- SET(dist) = SET(adj)
    RETURN ((MAX((dist values)) if everyone else null), dist)
// demo run: OUTPUT rumour_time(adj, set{'ada'})


## Reference solution (Python)

```python
from collections import deque

def rumour_time(adj, starters):
    dist = {s: 0 for s in starters}
    q = deque(starters)
    while q:
        v = q.popleft()
        for u in adj.get(v, []):
            if u not in dist:
                dist[u] = dist[v] + 1
                q.append(u)
    everyone = set(dist) == set(adj)
    return (max(dist.values()) if everyone else None), dist

if __name__ == "__main__":
    adj = {"ada": ["bo"], "bo": ["cy"], "cy": [], "dee": []}
    print(rumour_time(adj, {"ada"}))   # (None, ...) - dee never hears
```

## Edge cases

- Termination: name the update that guarantees the loop ends, and check it on the smallest input.
- First occurrence of a key not yet in the map — the default path must produce a defined answer.
- Empty or single-item input: decide what is returned and what must NOT be printed.
- Degenerate values: zero, negatives, and duplicates among the instance's data.


## Alternative approaches

- Multi-source BFS: put ALL starters in the queue at distance 0; answer = max distance.
- Rewrite the while-loop as a bounded for-loop over the data (or vice versa) and compare which version makes termination obvious.
- A plain list of (key, value) pairs instead of a map: fine at this size, but every lookup becomes a scan.
- **Cost.** Linear: one visit per item, a constant amount of work per visit; the alternatives shift exactly this cost.


## Common pitfalls

- Forgetting the visited set on graphs with cycles.
- An update path that never moves the state — the loop that never ends; test on an interval of size two.
- Reading a key before it exists (the first occurrence) instead of using the default path.
- Mutating the caller's list when the result was meant to be a fresh one — the demo where the input 'changes by itself'.
- Reporting the answer without the rule that produced it — the decision becomes uncheckable.
