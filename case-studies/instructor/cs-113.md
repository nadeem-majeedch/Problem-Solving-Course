## Reasoning walkthrough

**Worked instance.** two dice, 10,000 rolls

**Expected result.** demo prints '0.1704 exact: 0.1667' — the share of 10k rolls summing to 7 against the exact probability; the full distribution matches theory to within about a percent

**Method — simulation and randomness.** Walk the class through these moves:

1. Tell the story of one trial precisely (what is random, what is fixed?).
2. Choose the randomness source and any seed for reproducibility.
3. Run many trials; record the statistic per trial.
4. Summarise the distribution; compare against exact reasoning where possible.

**Where this class gets stuck.** One trial = roll two dice. The only skill is the loop and the comparison table. Expect the first
five minutes to produce unseeded randomness: results not reproducible as the
most common wrong turn; plan the reveal around it.


## Five-minute teaching sequence

Minute 0–1 — **Read and analyse.** Expect inputs, outputs, and at least
one stated assumption named; the deciding quantity here is the input
rule. Watch for: retelling the story without extracting the decision.
Minute 1–3 — **Develop an approach.** Expect a rule or a first-step
computation on the instance; a correct rule with an arithmetic slip is
partial credit. Watch for: reading an input key before it exists — the first occurrence needs the default path.
Minute 3–5 — **Compare and write.** Expect the update rule or loop
skeleton written down, pairs comparing orders of operations. If most
pairs stall, give the structure hint from the difficulty ladder
(below) whole-class rather than pair by pair.
Reveal and discuss — keep the reveal inside 10 minutes so the exit question still fits.

## Reference solution (pseudocode)

FUNCTION dice_sim(rolls, seed)
    r <- random.Random(seed)
    counts <- map{}
    REPEAT rolls TIMES
        s <- r.randint(1, 6) + r.randint(1, 6)
        counts[s] <- counts.get(s, default 0) + 1
    RETURN map{s: counts.get(s, default 0) / rolls for s in range 2..13}

## Reference solution (Python)

```python
def dice_sim(rolls=10_000, seed=42):
    import random
    r = random.Random(seed)
    counts = {}
    for _ in range(rolls):
        s = r.randint(1, 6) + r.randint(1, 6)
        counts[s] = counts.get(s, 0) + 1
    return {s: counts.get(s, 0) / rolls for s in range(2, 13)}

if __name__ == "__main__":
    sim = dice_sim()
    print(round(sim[7], 4), "exact:", round(6 / 36, 4))
```

The code is runnable as-is; executing the file prints the worked instance
so you can demo it live on the projector.


## Edge cases

- First occurrence of a key not yet in the map — the default path must produce a defined answer.
- Empty or single-item input: decide what is returned and what must NOT be printed.
- Degenerate values: zero, negatives, and duplicates among the instance's data.
- Rounding: say where values are rounded and why a last digit may differ between two correct attempts.


## Alternative approaches

- One trial = roll two dice. The only skill is the loop and the comparison table.
- Loop-first formulation versus a comprehension/direct-expression formulation — same result, different emphasis on state versus intent.
- A plain list of (key, value) pairs instead of a map: fine at this size, but every lookup becomes a scan.
- **Cost.** Linear: one visit per item, a constant amount of work per visit; the alternatives shift exactly this cost.


## Common pitfalls

- Unseeded randomness: results not reproducible.
- Reading a key before it exists (the first occurrence) instead of using the default path.
- Comparing floating-point values for exact equality instead of a tolerance (or rounding at the very end, not mid-computation).
- Reporting the answer without the rule that produced it — the decision becomes uncheckable.


## Reveal script

1. Display the case and start the timer (5 minutes). While students work,
   circulate and read shoulders; pick one conventional attempt and one
   surprising one for the board.
2. Ask first: 'What is one trial, what is random inside it, and what are you averaging over?'
3. Walk the worked instance (two dice, 10,000 rolls) on the board
   under the stated rule before any code appears; the class calls the
   next state at each step.
4. Surface the wrong turn directly: 'unseeded randomness: results not reproducible' — ask the room
   which quiet assumption it makes.
5. Show the reference Python, run it on the worked instance, and let the
   class compare with their own answers.
6. Close by naming the technique — "simulation and randomness" — and hand over the
   discussion prompt: **"How many trials would you demand before believing a 1-in-1000 event estimate?"**


## Assessment use

- **Formative use.** discussion-grade: mark assumption quality and rule precision rather than the final number, and expect the full cycle to run long.
- **Mini-rubric (10 points).**
  - *Structure (2):* inputs, outputs, and the binding constraint named before any computation.
  - *Method (3):* the stated moves executed — especially "Choose the randomness source and any seed for reproducibility"
    and "Run many trials; record the statistic per trial".
  - *Result (3):* the worked instance computed correctly (sum 7 ~ 16.7% (6/36 exact); distribution matches theory within…),
    and the answer survives the smallest and the boundary input.
  - *Communication (2):* assumptions stated; the answer reports which rule produced it.
- **Follow-up check.** A key appears that was never seen before: which line of your rule handles it, and what does it output?
