## Reasoning walkthrough

**Worked instance.** budget 20; posters A price 5 reach 40 each, B price 4 reach 30; wall space 3 m, A needs 1 m, B needs 0.5 m

**Expected result.** formulation: max 40a+30b s.t. 5a+4b<=20, a+0.5b<=3, integers >=0; best by enumeration: a=2,b=2 -> 140

**Method — brute force and search spaces.** Walk the class through these moves:

1. Describe the search space precisely (what is one candidate?).
2. Count the space before enumerating it.
3. Enumerate systematically to avoid duplicates and gaps.
4. Filter with the constraint; prune what cannot succeed.

**Where this class gets stuck.** Write objective and constraints BEFORE solving; then enumerate the small integer space honestly. Expect the first
five minutes to produce enumerating unordered items in every order (n! instead of c(n,k)) as the
most common wrong turn; plan the reveal around it.

## Reference solution (pseudocode)

FUNCTION poster_best(budget, wall)
    best <- (0, 0, 0)
    FOR EACH a IN range 0..budget div 5 + 1 DO
        FOR EACH b IN range 0..budget div 4 + 1 DO
            IF (5 * a + 4 * b <= budget) AND (a + 0.5 * b <= wall) THEN
                reach <- 40 * a + 30 * b
                IF reach > best[0] THEN
                    best <- (reach, a, b)
    RETURN best

## Reference solution (Python)

```python
def poster_best(budget=20, wall=3.0):
    best = (0, 0, 0)
    for a in range(budget // 5 + 1):
        for b in range(budget // 4 + 1):
            if 5 * a + 4 * b <= budget and a + 0.5 * b <= wall:
                reach = 40 * a + 30 * b
                if reach > best[0]:
                    best = (reach, a, b)
    return best

if __name__ == "__main__":
    print(poster_best())   # (140, 2, 2)
```

## Edge cases

- Empty or single-item input: decide what is returned and what must NOT be printed.
- Boundary positions: the first item, the last item, and the position one past each end (the i-1 / i+1 arithmetic).
- Rounding: say where values are rounded and why a last digit may differ between two correct attempts.


## Alternative approaches

- Write objective and constraints BEFORE solving; then enumerate the small integer space honestly.
- Loop-first formulation versus a comprehension/direct-expression formulation — same result, different emphasis on state versus intent.
- A table filled by hand before any code: for the size of instance here it is both a solution and the test oracle.
- **Cost.** Quadratic in the worst case: the nested passes revisit the data once per element; the alternatives shift exactly this cost.


## Common pitfalls

- Enumerating unordered items in every order (n! instead of c(n,k)).
- Comparing floating-point values for exact equality instead of a tolerance (or rounding at the very end, not mid-computation).
- Off-by-one at the boundary: the update that is correct for the middle of the data and wrong at the two ends.
- Reporting the answer without the rule that produced it — the decision becomes uncheckable.


## Reveal script

1. Display the case and start the timer (5 minutes). While students work,
   circulate and read shoulders; pick one conventional attempt and one

2. Ask first: 'What is the search space, and in what order will you try it?'
3. Walk the worked instance (budget 20; posters A price 5 reach 40 each, B price 4 reach 30; wall space 3 m, A needs…) on the board
   under the stated rule before any code appears; the class calls the
   next state at each step.
4. Surface the wrong turn directly: 'enumerating unordered items in every order (n! instead of c(n,k))' — ask the room
   which quiet assumption it makes.
5. Show the reference Python, run it on the worked instance, and let the
   class compare with their own answers.
6. Close by naming the technique — "brute force and search spaces" — and hand over the
   discussion prompt: **"Which constraint is cheapest to check first, and why does order matter?"**


## Assessment use

- **Formative use.** discussion-grade: mark assumption quality and rule precision rather than the final number, and expect the full cycle to run long.
- **Mini-rubric (10 points).**
  - *Structure (2):* inputs, outputs, and the binding constraint named before any computation.
  - *Method (3):* the stated moves executed — especially "Count the space before enumerating it"
    and "Enumerate systematically to avoid duplicates and gaps".
  - *Result (3):* the worked instance computed correctly (formulation: max 40a+30b s.t. 5a+4b<=20, a+0.5b<=3, integers…),
    and the answer survives the smallest and the boundary input.
  - *Communication (2):* assumptions stated; the answer reports which rule produced it.
- **Follow-up check.** Where does rounding happen, and which digit may differ between two correct implementations?
