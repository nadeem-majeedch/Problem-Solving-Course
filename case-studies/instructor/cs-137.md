## Reasoning walkthrough

**Worked instance.** Two backup designs with stated failure
probabilities: one 50-minute run failing with probability 1/10, versus
five independent 10-minute chunks each failing with probability 1/50.

**Expected result.** demo prints `plan A: clean 0.900, expected waste
5.0 min` and `plan B: clean 0.904, expected waste 1.0 min` — a clean
night is no failure (A: 1 − 1/10; B: (49/50)^5 ≈ 0.904), while
expected waste multiplies each failure probability by its cost (A:
0.1 × 50; B: 5 × 0.02 × 10).

**Method — risk, trade-offs, strategy.** Walk the class through these
moves:

1. Define "clean night" precisely per plan: A fails as a whole;
   B fails only if some chunk fails, and independence makes the
   five-chunk product legitimate: (1 − 1/50)^5.
2. Expected waste is probability × cost of the bad outcome, summed
   over outcomes: A has one failure mode worth 50 minutes; B has five
   modes worth 10 minutes each, so 5 × 0.02 × 10 = 1.0.
3. Read the two metrics *together*: B's clean-night edge over A is
   tiny (+0.004) but its waste is five times smaller — chunking buys
   cheap failures, not noticeably cleaner nights.
4. Name the load-bearing assumption: independence. A degrading disk
   correlates chunk failures, and the comparison bends; the
   recommendation must cite the assumption, not just the numbers.

**Where this class gets stuck.** Students compute E[failed chunks] =
0.1 and stop, or multiply 0.1 × 5 forgetting the per-chunk cost — the
discipline is writing "P(event) × minutes" for every line. Second
stall: treating 0.904 > 0.900 as the headline; the waste column is
the real differentiator.

## Five-minute teaching sequence

Minute 0–1 — **Read and analyse.** Expect "clean night" defined for
both plans. Watch for: conflating failed chunk with failed night.
Minute 1–3 — **Develop an approach.** Expect the four numbers; a
correct clean-night pair with a waste slip is partial credit. Watch
for: (1/50)^5 instead of (49/50)^5.
Minute 3–5 — **Compare and write.** Expect the recommendation with
its assumption named; pairs argue A vs B from the two metrics.
Reveal and discuss — keep the reveal inside 10 minutes so the exit question still fits.

## Difficulty adaptation

- **Simplify.** Compute plan A alone (one line), then plan B with the
  independence product given.
- **Extend.** Ask for the per-chunk probability p at which B's
  expected waste equals A's (p = 0.1) and what that means — chunking
  wins while per-chunk failure stays well under 10× the whole-run
  rate.
- **Hints (progressive).**
  1. *Re-orient:* "For plan A, one attempt per night: expected waste
     is P(fail) × minutes per failure."
  2. *Structure:* "Five chunks, independent: multiply the survive
     probabilities; waste is failed chunks × 10."
  3. *Near-answer:* the common wrong turn is multiplying P(fail)^5 —
     undo that choice and re-derive the step it breaks.

## Reference solution (pseudocode)

```
clean_A <- 1 - P_A
waste_A <- P_A * 50
clean_B <- (1 - P_B)^5
waste_B <- 5 * P_B * 10
recommend <- compare (clean, waste) under the independence assumption
```

## Reference solution (Python)

```python
P_A, COST_A = 1 / 10, 50
P_B, CHUNKS, COST_B = 1 / 50, 5, 10

if __name__ == "__main__":
    clean_a = 1 - P_A
    waste_a = P_A * COST_A
    clean_b = (1 - P_B) ** CHUNKS
    waste_b = CHUNKS * P_B * COST_B
    print(f"plan A: clean {clean_a:.3f}, expected waste {waste_a:.1f} min")
    print(f"plan B: clean {clean_b:.3f}, expected waste {waste_b:.1f} min")
```

The code is runnable as-is; executing the file prints the worked instance
so you can demo it live on the projector.

## Edge cases

- p = 0 for everything — both plans perfect; the comparison is about
  failure *structure*, visible only when p > 0.
- A chunk failure that also destroys the window (correlated cascade) —
  outside the stated model; the escalation discussion covers it.
- Expected waste equal but clean-night different — decide which metric
  the stakeholders buy; neither dominates automatically.

## Alternative approaches

- Simulate 10,000 seeded nights per plan — good lecture-29 preview;
  with independence stated, the analytic answer is exact and cheaper.
- Maximise probability of finishing *within the hour* instead of
  minimising waste — a different objective that favours B more
  strongly; worth surfacing.
- Serial retries inside the window (A with a 10-minute retry) — a
  hybrid plan; the window arithmetic (50 + 10 > 60) kills it, a
  useful constraint lesson.
- **Cost.** All arithmetic is constant-time; the real trade-off is
  assumption risk (independence) versus structural risk (all-or-
  nothing failure).

## Common pitfalls

- Raising the failure probability to the 5th power instead of the
  survival probability.
- Reporting expected failed runs (0.1) as expected minutes.
- Hiding the independence assumption inside "five chunks are safer".
- Concluding from clean-night alone and calling the plans equivalent.

## Reveal script

1. Display the case and start the timer (5 minutes). While students work,
   circulate and read shoulders; pick one conventional attempt and one
   surprising one for the board.
2. Ask first: "What does a *clean* night mean for each plan?"
3. Compute the four numbers on the board, room calling each
   probability.
4. Surface the wrong turn directly: 0.1^5 vs 0.98^5 — ask which one
   answers "no chunk ever fails".
5. Show the reference Python, run it on the worked instance, and let the
   class compare with their own answers.
6. Close by naming the technique — "expected cost with named
   assumptions" — and hand over the discussion prompt about the aging
   disk.

## Assessment use

- **Formative use.** discussion-grade: mark probability discipline and
  assumption naming over the final recommendation.
- **Mini-rubric (10 points).**
  - *Structure (2):* clean night defined per plan before computing.
  - *Method (3):* survival product for B; waste as P × cost for both.
  - *Result (3):* 0.900/5.0 vs 0.904/1.0 with units and rounding.
  - *Communication (2):* recommendation cites independence explicitly.
- **Follow-up check.** Double every failure probability: which plan's
  expected waste grows faster, and why?
