## Problem

Digit sum via loop vs recursion; then count the calls. Same result, different shapes; when recursion mirrors the problem's structure.

Your deliverable is the recurrence with base cases, the answer for the worked instance, and the memoised (or tabulated) version. If the problem is ambiguous anywhere,
state the assumption you are making and carry on — a stated assumption is
part of a good answer.

## Examples

- **Input:** n = 4723
- **Output:** digit sum 16 both ways; recursive version makes 4 calls; loop makes 4 iterations

Solve for the worked instance first. Then ask what would change if one
number, name, or condition were replaced by something stranger.

## What to notice

- f(n) = n%10 + f(n//10), base n = 0. Same recurrence shape as the loop - which is clearer?
- Trust the recursive call: if f(smaller) is correct, the transition is all you must get right.
- A DP table is the call tree, cached.
