## Problem

Same student appears with name variants and id typos. Design a matching rule with a manual-review queue; measure how much the rule catches vs leaves.

Your deliverable is the stated assumptions, the matching rule (what counts as the same student) made precise, and one borderline pair with your verdict. If the problem is ambiguous anywhere,
state the assumption you are making and carry on — a stated assumption is
part of a good answer.

## Examples

- **Input:** "Ada Lovelace" / "ada lovelace" / "A. Lovelace" / id "S2023-0471" vs "s2023-0471 "
- **Output:** match rule: lowercase+strip id first (exact); name fuzzy (initials + surname); manual queue for the rest

Solve for the worked instance first. Then ask what would change if one
number, name, or condition were replaced by something stranger.

## What to notice

- Design the rule in tiers: exact key match, normalised key match, fuzzy match, human queue - and report each tier's catch rate.
- Writing the rules IS the solution; code is transcription.
- Every assumption is a place where two good answers can differ.

## Discussion starter

After the solution is revealed, the class spends five minutes on this
prompt: **"Propose one extra rule that would change the verdict — is it an improvement?"**
